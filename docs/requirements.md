# 基礎需求

本文件只定義「要達成什麼」。任何做法、架構、階段規劃都不寫在這裡。

## 目的

用程式自動遊玩 SD Gundam G Generation ETERNAL，在無人看管的情況下，
通關使用者指定的關卡；當隊伍實力不足以通關時，程式要自行利用遊戲內
既有的手段（重複攻略可再次進入的關卡取得資源、強化與開發機體及駕駛員）
提升隊伍，然後再回來挑戰，直到通關或確認無法達成為止。

## 名詞定義

- **關卡**：遊戲內可從關卡選擇畫面進入、有明示勝利與失敗條件的一場攻略。
- **通關**：以遊戲自身的判定為準（結算畫面出現、關卡列表狀態改變）。
  程式內部的任何推測都不算數。
- **資源**：遊戲內可累積、可消耗、影響隊伍實力或行動能力的量化項目。
  目前已知至少包含資本與強化用素材；完整清單待確認（見文末）。
- **隊伍實力**：對「目前隊伍能否合理嘗試某一關卡」的判斷依據。
  這是程式必須具備的一種判斷，如何計算不在本文件範圍。

## 環境與前提

- 操作對象是一台經 USB 連線的 Android 實機，遊戲以橫向 2340×1080 執行。
- 遊戲沒有任何程式介面：能看的只有螢幕畫面，能做的只有觸控輸入。
- 執行期間使用者可能完全不在場。

## 需求

1. **指定與完成**：使用者指定目標關卡，程式自行完成從進入關卡到通關的
   全部過程，不需要人工介入。
2. **戰鬥自主**：關卡內的每一個戰鬥決策與操作都由本程式做出，
   禁止使用遊戲內建的自動戰鬥功能。
3. **資源控管**：程式要能判斷目前隊伍是否足以挑戰目標關卡；不足時，
   自行選擇並執行提升手段（刷資源、強化、開發），提升後再挑戰。
   資源的取得與消耗都必須服務於目標關卡的達成，不做無目的的損耗。
4. **遵守關卡條件**：每一關的行動以該關遊戲內明示的勝利條件與失敗條件
   為依據，而不是一套對所有關卡都相同的假設。
5. **誠實停止**：遇到無法繼續的情況——畫面無法辨識、同一件事重複失敗、
   找不到可行的提升手段——程式必須停止操作、保留原因與當下狀態，
   等待人工處理。禁止無限重試與沒有依據的隨機嘗試。
6. **過程可查驗**：每次執行都要留下足以事後重建過程的紀錄：
   做了什麼、當時看到什麼、為什麼停止。

## 待確認事項

- 資源項目的完整清單（資本、素材之外還有哪些）。
- 「指定關卡」的範圍：只含主線，或也包含活動關卡、每日關卡。
- 穩定完成與效率（時間、資源損耗）之間的優先順序。
