# 盤面掃描覆蓋模型 v3 實作規格（as-built）

> Type: spec—authoritative for the implementation; drift is a bug

2026-08-04 立檔。對應實作 `src/ggge_ai/runtime/coverage.py`（感知原語在
`src/ggge_ai/runtime/board.py`）。提案原文 `docs/survey-anchor-v3-proposal.md`
已實作，這份是落地後的權威敘述；程式碼裡不再重述本文件的任何內容。

骨架的一句話：**任何一張畫面的位置，只由畫面裡看得到的東西決定，永遠不由
「上一張位置加上這次的移動量」累加出來。** 第 1 到第 7 輪實機驗證修掉的問題
——量測凍值、靜態畫面誤判成移動、拼接錯位、單位數膨脹到真實數量的三倍——
全部是累加骨架的病：位置靠累加，每一次量測都是單點故障。

## 一、掃描流程（三階段）

### ZERO（歸零）

往西北連續用力推（`ZERO_CORNER = ("west", "north")`，兩個方向輪流），直到
兩個方向都連續 `STALL_CONFIRM` 次畫面不再變化＝鏡頭被地圖邊卡住。那一幀還
要**目視到角落至少一側的地圖終止邊**才算數——手勢被遊戲吃掉的畫面同樣不動，
目視的邊分得出兩者。

以那一幀錨定世界原點 (0,0)：座標在這裡是被**定義**的，不是量出來的。角落是
可重現的絕對位置，所以跨回合重新歸零會回到同一套座標，地圖幾何（格網、界線、
地標）不必重學。

角落幀讀不出格網時退一步再回來，上限 `ZERO_TRIES` 次；用完就誠實停在「沒掃
完」，不假裝完成。

完成條件：`_anchor` 成功（有格網、與已記地標不矛盾）→ 轉 TOUR。

### TOUR（沿邊繞圈）

`TOUR_ROUTE = ("east", "south", "west")`：向東推到東北角、向南推到東南角、
向西推到西南角。每一站的定位直接讀畫面裡的地圖終止邊——單側可見鎖一軸、角落
可見鎖兩軸。每一個方向推到「該側終止邊進畫面」或「連續 `STALL_CONFIRM` 次推
不動」為止，然後換下一個方向。

完成條件：`TOUR_ROUTE` 走完（route 清空）→ 轉 FILL。

### FILL（補中央）

地圖高於一個螢幕時中央帶會漏。挑一個待掃格聚類（`KnowledgeMap.choose`）往它
推，直到目標格進得了偵測帶。中央帶看不到終止邊，定位靠標記格或「畫面裡的單位
排列對回已記目擊」（`board.relocalise`），影像複驗消掉整數格歧義。

推不動（該推的方向都夾在邊上）就把聚類裡離質心最近的那一格退休
（`unreachable`）：那一格從任何到得了的鏡頭位置都看不清楚，硬要它只會原地空轉。
退休的一定是**聚類成員**——L 形聚類的質心根本不在聚類裡，退休它既不會讓目標
清單變短（活鎖），又把一格可能是 EMPTY 的格子跨代排除掉（＝無聲丟失）。一次
退休一格，迴圈才保證嚴格縮小。

目標格已經在偵測帶裡卻還是缺口＝它壓在 HUD 挖洞底下（`_escapes`）。洞在螢幕座標
固定不動，鏡頭一動格子就從洞底下移出來——所以「洞蓋著」不是永久事實，是這個鏡頭
位置的事實，不算這一步的話暫時被回合橫幅蓋到的格會當場退休。挪開的候選每一個都要
**真的**把格子挪到看得清楚的地方：躲開一個洞卻掉進另一個洞或掉出偵測帶的候選一律
不算數，不然兩個洞會把規劃器夾在中間來回空推。

推的方向算的是「目標格進不進得了偵測帶」而不是「離視野中心多遠」：目標已經在帶內
的那一軸推它只是把它推出去，而另一軸夾在邊上推不動——兩者一湊就是東西向來回空推
的活鎖。

沒有待掃格可挑時，還沒定界線的方向自己就是強制待掃格，往那邊推去找邊
（`_probe`）。

完成條件（`KnowledgeMap.complete`，建構性判準）：四面界線都定 ∧ 界內沒有
UNKNOWN／STALE。

### 回合交界（`expire`）

敵方回合鏡頭會被遊戲拉去演出，兩個回合之間的位移量不出來，所以 v3 不嘗試跨
回合接回去——直接推回西北角重新歸零。單位知識降級、地圖幾何（charted、界線、
地標）原封不動。推移次數的保險絲跟著歸零（見 `LEG_BUDGET`）。標記格的填色敵
方回合過完就沒了，位置與世界格作廢，**色簽留著**：同一個縮放檔位下顏色不變。

### 縮放變更（`reset`）

鏡頭的比例被動過：舊世界的像素座標與地標全部作廢，整個重來。標記連色簽一起
清——色簽記著一格填色的參考尺寸，換一個縮放檔位那個尺寸就是錯的。

## 二、定位（每一幀怎麼解出座標）

順序：先問地標（絕對），再逐個候選試，每一個候選各自過複驗。

1. **地標**：定位成功的幀看到哪一側的終止邊，就把那一側的世界像素記下來
   （`landmarks`）。往後任何一幀只要看得到同一側，那一軸的座標直接讀出來。
   同軸兩側都看得到而彼此差超過 `EDGE_TOLERANCE` 格＝至少一側不是地圖邊，
   兩個都不採信（挑一個信就是「量錯寫入」）。
2. **候選來源**，由強到弱：兩軸地標（`SOURCE_EDGE`）→ 標記格
   （`SOURCE_MARKER`）→ 沿用上一張（`SOURCE_STILL`）→ 單位排列比對
   （`SOURCE_MATCH`）。標記排在地標之後：兩者都絕對，但標記會被移動地圖弄掉，
   地標不會。
3. **每一個候選各自複驗**：候選座標套上去之後，這一幀的機體要落回知識圖已記
   的目擊（佔位一致性）。判準是**和差一整格的鄰居比**，不是固定的支持數門檻
   ——往沒看過的地方推的那幾幀，畫面上多數機體本來就還沒被記過。複驗**絕不與
   產生候選的那一次量測同源**：拿量測回頭替自己背書是恆等式不是複驗。一個候
   選過不了就換下一個，全部過不了才丟整幀（逐候選複驗是刻意的：稀疏地帶的排
   列比對會投出差幾十像素的候選，當場丟整幀會讓那一段連環丟幀掃不完）。
   讀得到地標的那一軸由地標說了算，候選只補另一軸——地標是絕對量，拿它去否決整幀
   等於連確定的那一軸也一起丟掉；合起來對不對由複驗裁。佔位一致性的鄰居**兩軸都
   要試**，不只補位那幾軸：地標算出來的軸不會跟自己矛盾，唯一驗得到它的地方就是
   這裡（東／南地標必然是在那一側還沒有地標時記下的，來自補位來源）。
4. **影像複驗**（佔位一致性沒有材料或同源時）：目視終止邊的位移（絕對量，
   任何週期內容都動不了它）→ 逐窗影像複驗。逐窗要**贏過自己差一整格的鄰居**
   才算背書：格線是週期訊號，差整數格的錯值照樣把線對得整整齊齊。取樣窗限在
   格線覆蓋的矩形內——**背景圖案不當位置證據**，不隨鏡頭動的星空層在整區量測
   裡面積佔優，它給的是「畫面沒動」的高信心錯答。
5. **對不回來就丟棄**：定位不出來的幀整張丟掉，不進緩衝、不重錨、不累積。連
   續丟到 `LOST_PATIENCE` 幀就推回角落重新歸零，成本有上限（地圖就這麼大）。

「畫面有沒有動」只回布林不回位移。**標記格優先**（純螢幕空間的問法，歸零段
照樣成立），兩幀有一幀看不到標記才退回逐精靈窗影像複驗。**「沒動」要有人指
著畫面說沒動**：問不出來一律當作動過——反過來寫會讓空白幀被判靜止，而靜止的
處置是沿用上一張的座標，那正是「量錯寫入」。

## 三、詞彙表

### 知識圖四態（`Knowledge`）

| 態 | 語意 |
| --- | --- |
| `UNKNOWN` | 沒掃過 |
| `EMPTY` | 掃過、沒單位 |
| `UNIT` | 這一代目擊到單位 |
| `STALE` | 前代有單位、這一代還沒重掃 |

EMPTY 與 UNKNOWN 是兩件不同的事實，STALE 是第三件；混在一起就沒有缺口可言。
`GAPS = (UNKNOWN, STALE)` ＝「還不是現況」的兩態：完成判準要求界內一格都不剩，
待掃格也只挑這兩態。

跨代衰效（`expire`）：UNIT→STALE（不是抹除，站位還有威脅評估的價值）、
EMPTY→UNKNOWN（敵可能移進來）。同一代裡已是 UNIT 的格**不因為某一幀沒目擊
就降級**——掃描發生在我方回合，敵單位不會移動，所以「看得清楚卻沒目擊」是偵
測漏不是離開的證據。

### 幀處置（`Reading.verdict`）

| 值 | 語意 |
| --- | --- |
| `ACCEPTED` | 定位成功、已寫進知識圖 |
| `STALLED` | 定位成功，但這一幀畫面沒動 |
| `BROKEN` | 試著定位但定不出來（或與地標矛盾），整幀丟棄 |
| `ZEROING` | 還在往角落推，本來就不談座標 |

ZEROING 與 BROKEN 分開記，流水帳才看得出這一幀是**沒必要定位**還是**定位失敗**。
兩者混記的話歸零段每一幀都長得像失敗。

### 座標來源（`Shift.source`，進遙測）

| 值 | 語意 |
| --- | --- |
| `SOURCE_EDGE` | 兩軸都由已記地標讀出 |
| `SOURCE_MARKER` | 標記格解出（一次兩軸） |
| `SOURCE_MATCH` | 單位排列對回已記目擊 |
| `SOURCE_STILL` | 畫面沒動，沿用上一張定位成功的座標 |
| `SOURCE_ANCHOR` | 歸零幀，座標被定義為 (0,0) |

### 丟棄理由

| 值 | 語意 |
| --- | --- |
| `EDGE_MISMATCH` | 同軸兩側地標彼此矛盾／角落幀與已記地標矛盾 |
| `UNMATCHED` | 一個候選都生不出來 |
| `PICTURE_REFUSED` | 影像複驗否決（含贏不過差一整格的鄰居） |
| `OCCUPANCY_REFUSED` | 佔位一致性否決（鄰居配得比較好） |

### 複驗放行者（`note["gate"]`，進遙測）

| 值 | 語意 |
| --- | --- |
| `BY_OCCUPANCY` | 佔位一致性支持數勝過所有鄰居 |
| `BY_EDGES` | 目視終止邊的位移與候選相符 |
| `BY_PICTURE` | 逐窗影像複驗贏過差一整格的鄰居 |
| `BY_LANDMARK` | 兩軸都由地標讀出，沒有補位軸要驗 |
| `BY_MARKER` | 標記格候選，直接放行（見第四節） |

放行者逐幀進遙測，流水帳才看得出這一幀憑什麼被收下。

### 其他

- **界線**（`boundary`）：四個方向各自「未發現／已定於某一格線」，一律**目視**
  （看到地圖終止邊），不從「推不動了」推論。界線＝該側最外一格看得清楚的格，
  線外沒有地圖，一定案就把線外的每一筆知識裁掉。第一次記下就不再改。
- **待掃格**（`frontier`）：界內、與已測繪區相鄰、還不是現況的格。限制在測繪區
  周邊是為了讓還沒定界線的方向有界可推。
- **退休格**（`unreachable`）：界內但從任何推得到的鏡頭位置都看不清楚的格（例如
  壓在回合橫幅底下的角落格）。退休是明寫的事實，逐 tick 進流水帳。
- **readable / covered**：`readable` ＝整格框在偵測帶內且不碰 HUD 挖洞（幾何）；
  `covered` ＝ readable 且沒有越過看得見的格網終止邊（＝敢說「掃過」）。EMPTY 毯
  要格線背書（`covered`），單位目擊只要讀得清楚（`readable`）——密度峰不依賴格線。

## 四、標記格（marker）

點地圖上沒有單位的空格會把那一格填滿顏色，移動地圖時填色留在原格。那是我們
**主動放置的絕對地標**：放置時知道它站哪一格，推移後在新幀找到填色就一次解出
兩軸。它同時是角落幀唯一有話說的停滯證言——逐精靈窗在那裡是瞎的（一把推移約
598px，把精靈映回前一幀就落到幀外，湊不到兩個窗一律回 blind）。

- **放置條件**（`_marker_spot`）：帶內、讀得清楚、沒有單位、點得下去，而且離掃
  描帶邊夠遠。「夠遠」＝一把推移的上限再加一格（`LEG_LIMIT` ＋格距），與判「要
  不要重放」用同一組餘裕，不然挑在邊上的標記下一 tick 立刻又要重放。
- **放得保守、找得寬鬆**：放置限在地圖區內（那裡上下都不是 HUD），偵測則整條掃
  描帶都認——標記被推出地圖區還看得見的話就不必重放。
- **偏好內容即將流入的那一側**：往東推的時候內容往西走，放在東邊的標記多活幾把。
- **世界格只在最近一幀定位成功時才記**：信念過期時換算出來的格座標會把一個絕對
  地標寫成絕對錯誤。沒記到的格由定位成功的那一幀補（`_adopt_marker`）。
- **失效是常態不是異常**：填色很容易被移動地圖弄掉，不在就退回既有的路，下一
  tick 補放，補放不記罰。
- **只有「點下去卻沒出現填色」才計入放棄門檻**（`MARKER_TRIES`）；連續失敗到上限
  就這一代不再嘗試（`marker_declined`），照舊流程走——標記是增強，不是硬依賴。
- **學到色簽要當場重找一次**：往後每一幀都靠重找認人，放置當下就重找不到的色簽
  是學了也不能用的。
- **反向跳躍視為遺失**：推移手勢被遊戲吃成點擊時標記會搬到手勢起手點，那是一次
  貨真價實的偵測卻是徹底的錯地標。有推移指令時要求標記隱含的內容位移與指令同號。
- **標記框內的目擊要濾掉**：那一格放標記時確認過沒有單位，填色本身可能被密度峰
  讀成一台機體。
- 遙測記 placed／survived／lost：存活統計是實機微調（色簽容差、放置位置偏好）唯一
  的材料。

## 五、資料結構欄位語意

`FrameView`（一幀的觀測連同它的座標系）：

- `lattice`：這一幀格線覆蓋的**螢幕**矩形（所以 `shifted()` 不必動它）。`None` ＝
  這一幀讀不出格線：幾何上「整格在帶內」照樣成立，但沒有格線背書就不敢說那裡有
  格子，EMPTY 毯一格都不鋪。
- `borders`：目擊到的那幾側終止邊在**螢幕**上的位置。與 `lattice` 框各說各話：框
  是取樣帶讀到的線位，邊界來自全幀掃描，看得到框外（實測東緣框到 1680、邊界在
  1763），拿框當界會把那之間明明有格子的地方一起漏掉。
- `sequence`：生這張 view 的那一次 `observe` 的序號，與流水帳同一列，join 得回
  tick／probe。

`Reading.detail`：定位的逐步驟自述（讀到哪幾側的地標、單位排列對上沒、影像複驗怎
麼說）。**純觀察者**：沒有任何判斷讀它，只有流水帳讀它。

`KnowledgeMap`：

- `charted` 是幾何（看過的格），衰效只動單位知識。
- `marks` 存目擊的**世界像素**座標，不是格心：對回已知地圖那一步要拿它跟當下的密
  度峰配對投票，量化到格心會讓靜態單位的票散進不同的桶、眾數湊不出來。
- `unreachable`：見第三節「退休格」。

`Survey`：

- `landmarks`：四側地圖終止邊的世界像素，跨代保留（地圖幾何不衰效）。
- `located`：最近一張**定位成功**的幀連同它的座標，是對回已知地圖與影像複驗的對手。
  定位失敗的幀不會動它——丟棄就是丟棄，不留半套狀態。
- `located_view`：那一幀讀到的螢幕事實（終止邊在螢幕上的位置）。複驗拿它跟這一幀的
  同一側相減，量出一個與像素位移量測互相獨立的內容位移。
- `clamps`：推不動當下的世界座標（軸別）；鏡頭離開就不再是夾住的狀態。
- `bumped`：那個方向被確認推不動幾輪（退休格跨代生效，所以要兩輪才算數）。
- `sighted`：最近一張 view 目視到終止邊的那幾側。**存側名不存座標**：終止邊在不在
  畫面上是螢幕事實，與解出什麼座標無關。
- `last_lattice`：最近一張 view 讀到的格線線位。挑標記格要的是格子的**螢幕**框，而
  那正是這一份線位——重讀一次是同一個答案，只是白花一次全幀取峰。
- `marker_cell` / `marker_screen`：標記站的世界格／最近一幀偵測到的螢幕中心（偵測不
  到就 `None`，但 cell 留著——下一幀可能又看得到）。

`observe` 的順序陷阱：標記的螢幕位置必須在停滯判定之後才更新，因為停滯判定問的正是
「上一幀記到的位置和這一幀偵測到的位置是不是同一點」。這一條在程式碼裡以註解就地標
記（全檔唯一一條）。

## 六、常數表

| 常數 | 值 | 單位 | 語意與訂定理由 |
| --- | --- | --- | --- |
| `EDGE_TOLERANCE` | 0.5 | 格距比例 | 目視終止邊與已記地標容許的落差。半格＝格座標還指得到同一格。也用於 `covered` 的遮罩容差：最外那一排格子的外緣**就是**終止邊，座標差幾個像素就會把它整排切掉。 |
| `OCCUPANCY_QUORUM` | 2 | 台 | 佔位一致性要幾台機體才裁得動「這個候選差了一整格」。一台配得上可能只是巧合——盤面上二十幾台，隔壁格剛好也站著一台的機率不低；兩台一起指向同一格才是證據。 |
| `PICTURE_SLACK` | 3 | 像素 | 逐窗影像複驗給兩個假設的對位餘裕。問的是「差一整格的兩個位置哪個對」，而候選本身帶著幾個像素的量測誤差——逐像素硬比會連正確的假設一起判否。 |
| `LEG_LIMIT` | `{x: MAP_REGION[2]/4, y: MAP_REGION[3]/4}`（400 / 155） | 世界像素 | 一次推移手勢的內容位移上限。前後幀要留得下八成以上的重疊，中央帶才對得回已知地圖。 |
| `NOMINAL_GAIN` | 2.3 | 內容像素／手指像素 | 手指行程換算內容位移的固定比例。v3 不再逐次修正它——推移只需要「往那個方向推一把」，距離準不準不影響座標。 |
| `STALL_CONFIRM` | 2 | 次 | 連續幾次畫面不動才算推到底。一次不算：起手點落在單位精靈上會被遊戲吃掉，畫面同樣不動。也用於「那個方向被確認推不動幾輪」（`bumped`）。 |
| `LOST_PATIENCE` | 3 | 幀 | 連續丟掉這麼多幀就推回角落重新歸零：帶著不知道位置的鏡頭繼續走沒有上界。同一個數字也是 `_contest` 的門檻：單獨一幀對不上可能只是偵測漏（代價是丟一幀），連著三幀都有兩台以上機體指著隔壁那一格就不是巧合。 |
| `ZERO_TRIES` | 3 | 次 | 角落讀不出格網時退一步再回來的次數上限。用完就誠實停在沒掃完。 |
| `STALE_WEIGHT` | 0.5 | 距離乘數 | 挑待掃格目標時含 STALE 的聚類的距離折扣。含 STALE ＝ 單位大概率在附近，威脅評估最需要。 |
| `LEG_BUDGET` | 200 | 次推移 | 推移次數的保險絲：只防**單一回合**內的失控，不是整場戰鬥的額度，也不是完成判準。跨回合累積的話十幾回合就燒斷，之後 `fused` 恆真、掃描永遠完不成＝整關卡死，所以 `expire` 一定要把它歸零。 |
| `MARKER_STILL_TOLERANCE` | 0.25 | 格距比例 | 標記格前後兩幀的位置差在這個比例的格距以內就算沒動。半格會把「滑了半格」讀成停滯，四分之一格仍遠大於偵測中心的抖動。錨定前沒有世界格網時退用色簽的參考尺寸（`board.MARKER_FALLBACK_PITCH`）。 |

## 七、紅線與不變式

1. **誠實量測**——兩條路都不准存在：
   - 無「量錯寫入」：定位不出來、或與已記地標矛盾的幀整張丟棄，一格都不寫。
   - 無「無聲丟失」：沒觀測到的界內格永遠是 UNKNOWN，待掃格一定把它排回補掃；
     退休格逐格明寫進流水帳（只記個數的話那條路就是無聲丟失）。
2. **邊界一律目視**（0723 定則）：界線只由「看到地圖終止邊」建立，永不從「推不
   動了」推論。地標與界線跨代保留，寫錯的代價是永久的，所以矛盾的處置是丟棄那
   一幀，不是改地標。沿用上一張座標的幀不准寫地標。
3. **定位不出來就丟棄，不重錨**：不進緩衝、不累積、不留半套狀態。連續丟到沒耐心
   就回角落重新歸零。
4. **手勢的量完全退出定位**：`Leg.expected` 只進流水帳與「畫面到底有沒有動」的影
   像複驗，不進座標計算。
5. **背景圖案不當位置證據**：不隨鏡頭動的星空層不得進入任何位移量測的取樣。
6. **STALE 不當現況**：`units()` 與 `sightings()` 都只回 UNIT，且四面界線都定之後
   只回界內——界外的 mark 是錯座標，算進台數就是憑空多出來的鬼影。

## 八、規劃層節流（`_clamped`）

「往這個方向再推收不到覆蓋」有兩個並列來源，任一成立即成立：

1. **目視終止邊**：畫面看得到那一側的格網終止邊，邊外是虛空。鏡頭移開之後那一側
   自然讀不到，下一幀就解除。
2. **推不動當下的世界座標**：連兩次推不動的那一點，而且那個方向要被確認過
   `STALL_CONFIRM` 輪。起手點連續兩次都落在單位精靈上就是連兩次推不動，跟到邊長
   得一模一樣；認一輪就封死的話，被吃掉兩把手勢會讓整欄格子當場退休。認第二輪最
   多多花兩把，而退休是跨代生效的。

這是**規劃層**的節流——定位與簿記一概不看它。
