# 實機測試計畫（run-book）

案例登記簿在 [live-verification-queue.md](live-verification-queue.md)（下稱「佇列」，
本文以佇列編號引用）；本文件是**執行順序與現場操作腳本**。2026-07-21 使用者
定案：計畫進行中在指定攔截點 **BLOCKING** 停下，請使用者把遊戲操作到指定
畫面，由當下 session 截圖入庫，作為之後離線驗證（fixture）的素材。

## 執行協定

- **前置**：adb 恢復（seat0 桌面實體登入；仍不通則手機重授權 USB 偵錯）→
  `uv run python scripts/capture.py` 確認截圖鏈路 → Keyguard 自理省電鎖 →
  開跑前 `discord-notify` 通知。
- **BLOCKING 攔截點協定**（每個標 `B` 的步驟）：
  1. session 停下，給出目標畫面與操作指引（一次一個畫面）。
  2. 使用者操作到位後回覆（離開電腦時 session 以 discord-notify 提醒）。
  3. session 立即 `capture.py` 截圖，**用像素探針/分類器程式驗證**是否為
     目標畫面（不目視；新畫面才派 subagent 讀圖確認）；不符就重來。
  4. 通過→記下截圖檔名與用途，繼續下一步。事後統一用
     `scripts/curate_fixture.py` 裁 fixture 入庫（像素級 PNG）。
- 裝置任務序列化：同一時間只有一個 agent 操作 adb。
- 同一步驟連續兩次失敗即停，問使用者（開發紀律既有規則）。
- 紅線提醒：結束回合對話框永遠選左「待機並結束」；絕不碰 AUTO 戰鬥；
  圖形鎖不關。

## 場次 A：非破壞驗證＋樣本蒐集（停留 TURN 1 hub，不推進戰鬥）

戰局現況：活動關 TURN 1 our-turn hub、一機已行動（可放棄退體力）。
場次 A 全程不執行任何單位行動，樣本攔截集中在此一次蒐完。

### A1. 切格線流程驗證（佇列 3）
- 跑 `scripts/grid_toggle_probe.py`：讀初始 toggle 狀態→切 ON→地圖 lattice
  驗證→切 OFF→驗消失→恢復初始。
- **樣本（腳本自動截，非 blocking）**：probe 停在設定頁 toggle=OFF 的當下
  多存一幀 → 補 T2 缺的 **OFF 態 fixture**（全庫掃過確認零樣本）。
- `B` **A1-B1（僅腳本導航失敗時啟用）**：請使用者手動開 戰鬥選單→設定→
  戰鬥籤，session 截 ON/OFF 兩態。
- 驗收：toggle 辨識與地圖格線出現/消失一致、設定復原、無誤觸 AUTO。

### A2. 縮放地圖驗證（佇列 2）
- 跑 `scripts/zoom_probe.py`：`zoom_out_max` 收斂序列（pitch 單調收斂）、
  方格開關往返、結束停 hub。
- **樣本（腳本每 pinch 自動存幀）**：中間 zoom 級距幀 → ① `zoom_at_max`
  閾值 113px 的邊界複驗（T1 開放問題）；② #25 縱向透視 row 模型的
  多級距格線數據（佇列 7 順帶餵料）。
- 加驗：對最終幀跑 `vision.zoom_at_max` 單幀判定，須與收斂迴圈結論一致。
- 加驗（T3 接線後）：逐地圖記錄最遠 zoom 的 col_pitch 對閾值 113 的裕度、
  收斂輪數（常需第二輪就該調 finger span/容差）；首次實跑留意流水帳
  `zoom_step`／`survey_abort` 事件——**T3 之後 zoom 收斂失敗會讓每場
  （含非 intel 戰鬥）以 survey_abort 收場**，這是 fail-fast 本意但首跑
  要有預期。
- `B` **A2-B1（可選）**：反向 pinch（拉近）腳本若未備妥，請使用者把地圖
  拉到**最近** zoom 且格線開啟，session 截圖 → 拉近端負樣本。

### A3. map_view 退頂層驗證（佇列 2 附屬）
- 腳本點選一台**未行動我方單位**進 unit_move 疊加層（僅選取，安全），
  `ensure_max_view` 應經遊戲內返回鈕退回 hub；再驗 modal 態（開單位詳情
  →自動關閉）。**絕不進行到行動執行**。
- **樣本（順帶自動截）**：unit_move 實況幀 → `map_view_state` fixture 補真
  收合/選中態樣本（現用 mode_label 舊圖）。

### A4. 單位詳情／基本資訊樣本蒐集（T8 缺口，全 BLOCKING 場）
背景：MP 只出現在「基本資訊」視圖與動作選單頂部面板；全庫僅一張含 MP
樣本、敵方 MP 零樣本；「基本資訊」切換鈕座標未標定（自動化做不到，
必須請使用者操作）。

- `B` **A4-B1**：我方單位 → 開單位詳情 modal（停在「組合資訊」tab）。
  截圖 → 離線標定「基本資訊」切換鈕座標（subagent 讀圖）＋modal 對照組。
- `B` **A4-B2**：同一單位 → 切到**基本資訊**視圖。截圖 → `classify_unit_detail`
  basic 正樣本第二張（解單樣本過擬合）＋SP/MP 轉錄
  （與 modal SP 比對＝SP/MP 語意釐清的直接證據）。
- `B` **A4-B3**：關閉後點一台**敵方**單位 → 詳情 → 基本資訊。截圖×2
  （modal＋basic）→ 敵方 MP 首批樣本、敵我佈局差異確認。
- `B` **A4-B4**：選我方單位停在**動作選單**（頂部 HP/EN/MP 小面板可見，
  不點任何行動）。截圖 → `read_unit_action_panel`（T8 stretch）樣本。
  完成後用返回鈕退出，不執行行動。
- 每張截圖當場用 `vision.classify_unit_detail`／`read_unit_detail_basic`
  驗（T8 已整合）。
- T8 離線成果帶出的補驗清單：①第二張我方 basic 視圖（不同機組，解單樣本
  過擬合＋驗版面漂移）；②基本資訊欄位出現數字 '9' 的樣本（glyph 未經
  本視圖渲染驗證）；③2 位數移動力機組（現用窄框防「5」讀成「51」，
  需確認不裁字）；④動作選單頂部 MP 是更小疊色條的渲染，現有字模讀不出
  ——要做 form D 讀取需從截圖裁專用 glyph；⑤戰鬥力漸層逗號字型刻意
  不讀，若未來要讀需專用字模樣本。
- SP/MP 語意證據（已有一組）：modal SP＝basic SP＝15 同值；MP 5/12 為
  current/max 型動態資源。A4-B2/B3 截圖時順帶再驗一組（不同機組），
  供使用者定案 MP 是否進 sim/schema。

### A5. 出擊機雙V樣本（佇列 5，條件步）
- 偵測器已落地才驗（目前未實作）；無論如何截一張 hub 全圖存證——本戰局
  turn 1 仍有多台滿血未行動，是 VV 窗口的天然樣本。

### A6. 機會樣本（場次 A 順帶）
- hit 字型 '3'：若任何畫面出現含 3 的命中率，多存一幀（佇列缺樣本清單）。

### A7. 遊戲內系統說明蒐集（MP 基礎系統，全 BLOCKING）
- `B` 請使用者開啟遊戲內「幫助／系統說明」找 MP／激昂／テンション相關
  條目，逐頁停留由 session 截圖 → 離線轉錄（遊戲內說明=規則文本的畫面
  權威，優先於一切網路來源；使用者裁決階段加成「有出入」，以此為準
  複核 `docs/mp-tension.md` §1）。

- 應戰四假設逐一驗：頭像槽算術定位 tap、行動選擇 (2042,924) 估計值、
  武器鈕順序=spec 順序、SHORT 深色可用圖示 V 閘門。
- 機會樣本：weapon_select/battle_prep 實況幀、SHORT 深色可用圖示、

  清零、跨回合行為、是否必暴、門檻武裝耗不耗 MP。每測一項前後各截一張
  基本資訊視圖（同時累積 T8 樣本）。多數項需 `B` 攔截由使用者操作
  （MPアップ 技能發動、指定攻擊目標）。

## 順序設計理由

1. **非破壞 → 樣本 → 大鏈路 → 破壞性**：A 場全程不消耗戰局，失敗可重試
   無成本；B 依賴離線整合完成故排第二；C 會推進戰局不可逆，殿後。
2. **樣本攔截集中場次 A**：所有 BLOCKING 點都在 TURN 1 hub 同一狀態面，
   使用者一次到位連續操作，不用來回切換情境。
3. **一次實機、多重回收**：A2 的 pinch 逐幀同時餵 zoom 閾值、#25 透視
   模型；B 的掃描幀同時餵批A/批B 數據與拼接回歸——每次上機都最大化
   離線可用產出，之後的開發批次少上機。
