## 一、(1) 落點與語意

```
Survey
 ├─ sighted: frozenset[str]        ★新——最近一次收下的 view 的 edges（側名，不是座標）
 ├─ observe()  → view 建好就寫 sighted（大陸與島嶼同一行，BROKEN 早退那條不寫）
 ├─ _anchor()  → 錨定幀同樣寫
 ├─ _clamped(direction)            ★改——目視邊與撞邊線並列，任一成立即成立
 │    ├─ direction in self.sighted          ← 新來源：邊外是虛空
 │    └─ |offset[axis] − clamps[direction]| < EDGE_SHIFT_PX   ← 舊來源：推不動
 ├─ _aim()   → 方向選擇 continue 過被夾的方向        （呼叫 _clamped，未改一行）
 ├─ _probe() → 方向輪替過濾被夾的方向                （呼叫 _clamped，未改一行）
 ├─ reset()  → 清 sighted（縮放換掉整個畫面內容）
 └─ summary()→ 多一個 "sighted" 欄位進流水帳
```

**這是規劃層的節流，量測與簿記一行未動**：`measure_pan`／`_snap`／`null_check`／
`_resolve_columns`／`absorb`／`_sight_edges` 全部原封不動，`sighted` 只被 `_clamped`
讀。旗（`chart.boundary`）與 clamp 是兩件事：旗跨代保留、會裁掉線外的知識；
`sighted` 只活到下一幀，不寫進任何知識。

### 為什麼「邊在畫面裡」就等於「往那邊沒有收益」

`read_span` 的終止邊判準要求最外一條線之外整整一個格距的取樣條同時安靜、暗、而且比
內側安靜得多（v2.6 標定）。那一條之外沒有格線＝沒有地圖，所以往那個方向推只是把虛空
推進畫面。而**邊內那一段本來就已經在偵測帶裡**：西終止邊落在 `GRID_REGION` 帶內
（x ≥ 150＋一個格距），偵測帶 `UNIT_DENSITY_REGION` 從 x150 起算，兩者之間沒有夾層。

### 為什麼記側名、而且島嶼期的 view 也算

終止邊在不在畫面上是**螢幕事實**，與里程計解出什麼偏移無關——這正是它跟 `clamps`
（記世界座標）的差別。島嶼期最需要它：`_sight_edges` 只跑大陸那條路，島上看到的邊
**定不了旗**，第 6 輪 t28-t31 就是這樣對著已經在畫面裡的東緣連推四把。

### 解除

`sighted` 每一次收下的 view 都整個覆蓋。鏡頭離開邊，下一幀 `edges` 不含它，clamp 當場
解除。`_abandon`（丟棄世界）刻意**不清**——那裡畫面沒變，側名照樣成立，而且緊接著的
`_anchor` 會覆蓋它；`reset`（縮放）清掉——縮小之後同一側可能露出更多地圖。

## 四、t32／t38 兩次世界重開的成因鏈

逐 tick 追島嶼計數器（`islands.reset` 兩次遞增都伴隨 `discarded`、`merge` 為 null）：

| 重開點 | 那座島出生於 | 島內 6 個 view | 成因 |
| --- | --- | --- | --- |
| t32-precheck | t29-leg（broken unmeasurable） | t29-leg／t30-pre／t30-leg／t31-pre／t31-leg／t32-pre | **`ISLAND_BUDGET`（6）耗盡**，`_reanchor` 一次都沒解出偏移 |
| t38-precheck | t35-leg（broken unmeasurable） | t35-leg／t36-pre／t36-leg／t37-pre／t37-leg／t38-pre | 同上 |

`_abandon` 把 `chart` 整個丟掉重錨，**四面旗跟著作廢**：

- **西旗**：t1 目視定案、一路撐到 t23。t32 重開時的錨定幀（t32-precheck）畫面裡是
  east＋south，沒有 west——西旗從此消失，之後 45 把平移沒有任何東西擋著往西推。
- **東旗**：t27 目視、t32 重開時被錨定幀重新定上（那一幀有 east）。t38 重開的錨定幀
  （t38-precheck）只有 south——東旗也消失。最終 `bounded` 只剩 `north`／`south`。

### clamp 對這條鏈的預期影響（**不是量測，是預期**）

- **第一座島**：6 個 view 裡有 3 個來自「東向空推」那幾 tick，而且 t30／t31 的真實位移
  是 0。`relocalise` 要的是視差——同一批單位在兩個位置的星座差。零位移的幀對重錨毫無
  貢獻。clamp 會把那三把改推別的方向，島內的幀因此帶著真視差，重錨成功的機會變高。
  **成不成功離線斷不了**（換了方向就是另一批幀），所以本節只記預期。
- **第二座島**（t35-t38）：三把都是西向，而那幾幀畫面裡只有 south——**clamp 完全不會
  介入**，第二次重開照樣會發生。
- **旗弄丟這件事 clamp 治不了**：`sighted` 是逐幀證言，世界一重開它下一幀就被新畫面
  覆蓋，救不回跨代的旗。交辦單明令本批不為 reset 另發明機制，所以這裡只記錄。

### 連帶：合成世界的兩組擺位

合成世界的鏡頭行程只有 476×300px（畫布 2816×1380 對螢幕 2340×1080），比實機小得多，
所以那個夾層在它身上是**死結**——實測 `readable` 對 chart 格 (0,−1)／(1,−1) 從 77／168
個鏡頭位置掉到 **0 個**。原本擺在那裡的單位因此永遠找不到，8 條覆蓋測試＋2 條 stage
測試當場紅。

處置：把落在夾層裡的那一格擺位往南挪（`UNITS` (3,2)→(3,5)、`SPREAD` (2,2)→(2,5)），
理由寫在常數上方。**這不是放寬斷言**——那個位置在新幾何下是「設計上放棄」的格，要求
測試斷言「一定找得到」等於斷言一件假的事；退休行為本身另有
`test_the_corner_cells_the_camera_can_never_expose_are_retired_out_loud` 專門釘著，沒動。

另有一條 stage 斷言改了：`test_the_survey_completes_when_the_frontier_empties` 原本釘
「收尾那一 tick 是掃描的平移」，現在收尾可能是「角落格退休」那一 tick（回 `DONE_STEP`）。
改成釘「這一輪確實走過掃描的平移」＋「收尾是掃描的平移或 DONE」，其餘斷言
（synced、單位數、
再叫一次仍是 DONE）不動。

## 七、設計決定清單

1. **`sighted` 存側名不存座標，且島嶼期照記。** 備選是只認大陸 view（旗與 clamp 語意
   一致）。不取：t28-t31 那四把正好全在島上，只認大陸就漏掉本批一半的收益，而終止邊
   本來就是螢幕事實、不依賴偏移解對。
2. **BROKEN 那一幀不更新 `sighted`。** 交辦單寫「最近一次 accepted view」，照字面走。
   `_isolate` 也會替 broken 幀建 view，但那一幀的量測沒過閘，語意上不算收下。
3. **`_abandon` 不清 `sighted`、`reset` 清。** 前者畫面沒變（而且緊接著重錨會覆蓋），
   後者整個畫面內容換掉。誤留一個舊側名的代價不對稱：`_aim` 兩軸都被誤夾就退休目標格，
   而退休是跨代生效的。
4. **`_aim`／`_probe` 一行未改，全靠 `_clamped` 收斂。** 備選是在兩處各寫一次目視邊
   的判斷。不取：兩個來源要「並列、不互相覆蓋」，寫在同一個述詞裡才保證語意一致。
5. **`summary()` 多吐 `sighted`。** 新增一道規劃閘卻沒有遙測，實機對帳時分不出
   「這一把平移沒發是因為 clamp」還是「前緣空了」。既有 `bounded` 就是同款寫法。
6. **右上洞停在 y95 而不是貼齊 y88 或挖到 y100。** 88 是鈕像素的實測上界，y100 會吃掉
   貼在鈕下方的真單位血弧（t35 實測）。95 給 7px 餘裕又不越線。
7. **左上洞按實測 x154-437 加 ~9px 邊距，不與橫幅洞合併。** 合併成 `(0,0,470,326)` 在
   格數上完全等價（中間 72px 夾層本來就塞不下一格），但兩個矩形留得住量測值，日後鈕
   改位置時看得出動的是哪一塊。
8. **fixture 依機制拆兩條、用 `forbidden` 而不是把船體峰寫進 `units`。** 見第六節。
9. **合成世界擺位往南挪，而不是放寬「每一台都找得到」。** 見第五節末。
10. **④ still 證人 k=0 回收沒做。** 明令緩收。

## 八、爭點

1. **clamp 救不到那 45 把東西震盪的平移（0/37），交辦單的預期要修正。** 數字在第三節。
   它救到的是另外 8 把（10.1%），其中 3 把當場斷鏈。震盪的真因仍是 v2.7 第六節
   那條：手勢推不動
   鏡頭。**下一批若還要打效率，該打的是致動端，不是規劃層。**

2. **左上鈕的洞代價不小，請使用者確認要留。** 單幀 3.0% 可讀格，加上一條幾何夾層——
   螢幕 x<446 那幾欄只在 y≥326 讀得到，鏡頭夾在西北角時那幾格直接退休。合成世界因此
   動了兩組擺位、改了一條 stage 斷言（第五節）。如果嫌貴，**只留右上那個洞是零代價的
   選項**（右上洞不動任何測試，實測完全無副作用），代價是左上鈕的假峰留著。

3. **旗在世界重開時弄丟，本批沒治。** 成因鏈定讞是 `ISLAND_BUDGET` 耗盡（第四節），
   兩次都是。交辦單明令不另發明機制。可考慮的方向（未實作、未評估）：`_abandon` 保留
   邊界旗要先解決「新世界的格座標與舊世界對不上」，那不是小改。

4. **右上洞的深度只在 3 幀上校過。** t19／t20／t35 的血弧位置決定了 y95 這個數字。若
   別的關卡血弧貼得更高，洞可能又開始吃單位；反過來若某些狀態下鈕更高，假峰會回來。
   實機對帳項。

5. **本批純離線。** 實機要看的：`survey_summary` 的 `sighted` 欄位在南終止邊那 110 幀
   裡是不是穩定含 south（clamp 有沒有真的生效）、`cells.unit` 對真值 28 會不會因為 HUD
   兩鈕消失而下降（預期降 1-2，船體假峰沒修所以仍會膨脹）、以及西北角退休格數有沒有
   因為新洞明顯變多。
