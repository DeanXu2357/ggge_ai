# 標記格定位批導覽（0804）

背景移除批（`826a4ab`，相位相關／整幀差／重疊區量測整批退場）留下 16 紅測
——剩下的「畫面有沒有動」判準（逐精靈窗 `null_check`）在角落幀是瞎的，歸零
確認不了推到底。本批用遊戲的新事實補上替代證言，並一併解決 TOUR 段排列比對
候選給錯位置的連環丟幀（第 10 輪快照問題①）。

**遊戲事實（使用者實機確認＋探針釘死）**：點地圖上沒有單位的空格，那一格填
滿半透明青色（下稱標記格）；移動地圖不點新東西就留在原格；點別的空格＝搬過
去；再點同一格無變化；點到有單位的格＝選取單位（不填色）；敵方回合過完消失；
點擊不會使鏡頭置中。選取時格子上方另掛一個地形小徽章（深底紫圖示）。

## 設計一句話

標記格＝我們**主動放置**的絕對地標：放置時知道它站哪一格（世界格 W），推移
後在新幀找到填色，`offset = grid.centre_of(W) − 填色螢幕中心`，一次解出兩軸。
地圖終止邊是被動地標（常不在畫面裡），標記想放哪就放哪——但**遺失是常態不
是異常**（使用者警告：推移容易弄掉填色），不在就退回既有候選路，下一 tick
補放，不記罰。

## 呼叫鏈與執行順序

### 像素層（runtime/board.py，+165 行，零刪改）

- `learn_marker(before, after, tap_point)`：放置當下前後幀相減，取點擊點附近
  （1.5×格距內）、一格大小（0.5–1.5×格距）的最大變化色塊，學 HSV 色簽（中位
  數）＋參考尺寸。**色簽是學出來的不是硬編的**——所以不需要預先標定顏色。
- `find_marker(frame, signature, region, holes)`：色簽容差內、一格大小、唯一
  贏家（第二名面積 <0.5×第一名）的連通塊中心。色相環狀拆段（`_hue_bands`）。
- 常數集中一處：`MARKER_TOLERANCE (10,60,60)`、`MARKER_CHANGE_LEVEL 30`、
  `MARKER_PITCH_SPAN (0.5,1.5)`、`MARKER_FALLBACK_PITCH 90`、
  `MARKER_NEAR_PITCH 1.5`、`MARKER_RUNNER_UP 0.5`。探針實測後**全部維持原值**
  （見下方實機證據）。

### 世界模型（runtime/coverage.py）

`Survey.observe` 每幀的順序：

1. `_spot_marker`：用色簽重找標記→存活統計（有推移指令時）＋方向健全性
   `_jumped`（標記隱含位移在指令軸上要同號，防推移被吃成點擊把標記搬到手勢
   起點）。
2. `_unchanged(..., spotted)`：**標記優先**——前後幀都看得到就比螢幕位置
   （容差 0.25×格距），純螢幕空間、歸零段照樣成立；看不到才退回逐精靈窗
   `null_check`。這就是 16 紅測的解。
3. `marker_screen` 更新（刻意排在停滯判定之後——那一關問的正是新舊位置）。
4. `_zeroing`／`_place` → `_candidates` 順序：雙軸地標 → **SOURCE_MARKER**
   → 沿用上一張 → 排列比對。地標軸照舊逐軸覆蓋候選軸。
5. 複驗 `_corroborated`：佔位一致性的否決與背書照常適用（標記與目擊不同
   源）；`_pictured` 終止邊檢查照常；**只有走到 `_outbids` 逐窗複驗才對
   SOURCE_MARKER 直接放行（gate=BY_MARKER）**——那個裁判在稀疏幀是瞎的，
   正是標記要補的洞。
6. 定位成功 → `_adopt_marker` 補記世界格（放置當時未錨定或信念過期的標記
   只有螢幕位置，是純停滯證言）。

放置決策 `marker_request`（stage 層每 tick 問一次）：

- 要放的條件：看不到標記，或離掃描帶邊 < 一把推移上限＋一格。
- 挑格 `_marker_spot`：格線覆蓋框內、掃描帶內、MAP_REGION 內（**放得保守**
  ——那裡點下去才打得到格子；偵測用掃描帶全幅＝**找得寬鬆**）、避 HUD 挖洞、
  格內外半格無目擊、`check_tap` 過得了（危險帶白名單）、偏好內容即將流入的
  那一側（`_inflow`＝下一把推移方向）。
- 掃完／保險絲燒斷／這一代已放棄（連續 3 次點不出填色）→ None。

生命週期：`expire()`（敵方回合）清位置與世界格**留色簽**；`reset()`（縮放）
連色簽一起清；`_rezero()` 不清——鏡頭迷路時標記還在畫面上，它的候選讓下一幀
直接重定位，這正是它比終止邊強的地方。

防污染 `_unmarked`：填色會被密度峰讀成一台機體（實機證實），落在標記框內的
目擊一律濾掉（放置時確認過該格無單位，我方回合掃描期間無人會移進去）。

### 執行器（stage/survey.py）

`survey_board` 每 tick：precheck 讀幀 → `marker_request` 非 None 就走 `mark`
微步驟（點擊＋收確認幀＋`learn_marker`，**這一 tick 不推移**，一 tick 一操作
不變）→ 否則照舊 `plan_leg`／推移。微步驟名 `mark`／`mark:miss`。確認幀不進
observe（它答的是「填出顏色沒」，不是位置證據）。遙測每列加 `marker` 欄
（cell/screen/seen/placed/survived/lost）。

## 爭點（review 時值得盯的地方）

1. **BY_MARKER 自我放行的邊界**：佐證不得與候選同源是本專案鐵律，標記候選
   在稀疏幀（無佔位材料、無終止邊）確實是自己背書自己。裁決理由：上游否決
   權完整保留，且 null_check 在那種幀本來就答不出話（decisions 0804 第一
   條）。殘餘失效模式：填色被弄掉後，畫面上剛好有色簽容差內、一格大小、唯
   一贏家的同色美術→錯候選在稀疏幀直接進圖。實機首輪未觀察到；若發生，候
   選是「連續 N 幀不見就棄世界格」。
2. **方向健全性只看指令軸**（`_jumped`）：垂直軸的跳動抓不到，靠佔位否決
   兜底。
3. **停滯證言的優先權**：標記說「沒動」就是沒動，null_check 不再被問。標記
   被誤認（見爭點 1）時停滯判定跟著錯——同一個殘餘失效模式，同一個候選解。
4. **`marker_cell` 在偵測不到時保留**：下一幀可能又看得到；代價同爭點 1。
5. **測試鷹架改動**（判準未變）：`zeroed()` 先放標記（那就是被測流程）；
   sweep 預算 45→60（mark tick 佔 tick）；tour 測試鏡頭改按指令行程移動
   （原 300px 固定值超出 y 軸推移上限，構造性超出設計包絡）。
