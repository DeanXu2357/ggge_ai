# 盤面透視變形離線量測（0809）

離線分析，未改動 `src/`。分析腳本與圖表在
`docs/reviews/perspective-measurement/`
（`measure.py` / `analyze.py` / `analyze2.py` / `analyze3.py` / `centre.py` / `plots.py`）。

## 0. 結論先講

1. 盤面是**單一固定的平面單應性**，而且它在螢幕空間裡是常數——與鏡位（pan）無關。
   橫線間距與縱線間距都隨螢幕 y 線性增長，**橫線的相對增長率剛好是縱線的兩倍**
   （實測比值逐 run 1.98 / 2.26），這是「格距 ∝ 1/w²、欄距 ∝ 1/w」的平面投影簽名。
2. **主要誤差在縱線不在橫線**。橫線用均勻格距的全域偏差只有 0.178 格（p2p），
   縱線把斜格當垂直線的誤差在螢幕頂帶最大 0.496 格、底帶 0.271 格，
   是 aim 閘 0.25 格容差的 1.1–2.0 倍。
3. `SCREEN_CENTRE` 現行值 `(950, 540)` 的 x 錯了 **220px（2.42 欄）**。
   21 筆置中樣本一致落在 x≈1170（＝2340/2，螢幕真中線），y≈553。

## 1. 方法

### 素材

| run | 窗幀數（量測用） | 來源 |
|---|---|---|
| `20260809-031256` | 437 window 事件 → 437 幀 | 量測當下在 `data/runs/`，量測後已被主 session 封存成 `.tar.gz` |

合計 758 幀進量測、747 幀取得可用的橫線列。

### 偵測

沿用 `ggge_ai.runtime.board` 的原語 `_highpass`（高斯高通取格線脊）與 `_ridges`
（脊峰擷取），**刻意繞過 `_trim` / `_plausible` 兩個均勻性閘**——那兩個閘會把
「間距不均勻」的幀整個丟掉，正是我們要量的東西，留著就是自我審查。
`find_lattice` 仍逐幀跑一次，只用來對照它自己回報的格距（見 §3.4）。

- 量測窗：x 500–2280、y 250–960（避開左側按鈕欄、頂部 AUTO 列、底部訊息條）。
- 橫線：整窗 `mean(axis=1)` 投影取脊，最小間距 45px。
- 縱線：切六個重疊的 y 帶（260-400 / 380-520 / 500-640 / 620-760 / 740-880 / 820-955），
  **每帶各自** `mean(axis=0)` 取脊——縱線是斜的，全高投影會把線攤成寬丘。
- 斜率：同一條縱線在相鄰兩帶的位置差 ÷ 帶心 y 差（57 878 筆）。
- 清理：取「相鄰間距落在合理帶內、且逐差變化 ≤12px」的最長連續段。

### 2.3 這是平面單應性，不是隨便一條曲線

平面在針孔相機下（橫線水平的情形）：欄距 ∝ 1/w、列距 ∝ 1/w²，
所以 `列距相對斜率 = 2 × 欄距相對斜率`。實測：

| run | row 相對斜率 | col 相對斜率 | 比值 |
|---|---|---|---|
| 011740 | 2.191e-4 | 1.109e-4 | **1.98** |
| 031256 | 2.426e-4 | 1.074e-4 | **2.26** |

另一條單應性預測：**同一條 y 帶內，縱線必須等距**（x 對欄序是仿射的）。
實測帶內線位對「一次式」的殘差：中位 0.39px、p95 1.72px、max 22.7px
（n=25 920）。成立。

兩條獨立預測都對上 ⇒ 用完整單應性描述這個盤面是有物理根據的，不是硬湊。

## 3. 模型擬合與殘差

三個候選（橫線軸）：

- **(a) uniform**：`V(y) = y / P`，P=87.05（全域最佳；journal 記的世界 row_pitch 是 86–87）
- **(b) affine**：格距對 y 一次式 `pitch(y) = p0 + k(y-650)` ⇒ `V(y) = ln(p0+k·Δy)/k`，
  擬合 p0=88.00、k=0.02050
- **(c) homography**：`pitch(y) = p0·(1+k₂Δy)²` ⇒ `V(y) = -1/(p0·k₂·(1+k₂Δy))`，
  擬合 p0=88.00、k₂=1.180e-4

`V` ＝把螢幕 y 換成「世界列座標」，單位就是格；整數 V ＝一條格線。

### 3.4 週期不一致：另一條與模型無關的系統誤差

`aim_drift` 把兩個相位相減，但兩邊用的**週期不是同一個**：

- 實測側 `board.lattice_phase` ＝ `lattice.rows[0] % lattice.row_pitch`，
  而 `lattice.row_pitch` 是那一幀的中位間距——758 幀實測分布
  **82 – 87（中位 85、p5 82、p95 87）**，隨格網落在螢幕哪一段而變。
- 期望側 `sweep.aim_drift` ＝ `(grid.phase - offset) % grid.row_pitch`，
  `grid.row_pitch` 是錨定當時固定下來的 86–87。

同一條線用這兩個週期取相位，差值：中位 0.052 格、p95 0.156 格。
這一項**與模型無關**，就算橫線模型完全正確它也還在。

（縱線同理：`lattice.col_pitch` 實測 88–93，中位 91。）

### 3.6 分帶結論：0.25 格容差下誰能安全過關

數字＝該帶的最大 |偏差|（格），全域去平均、不准每幀重擬合。

| 軸 | 模型 | 頂帶 250-450 | 中帶 450-700 | 底帶 700-870 | 判定 |
|---|---|---|---|---|---|
| 橫線 | uniform | 0.121 | 0.057 | 0.045 | 單看勉強過，加 §3.4 的 0.156 就越界 |
| 橫線 | affine | 0.001 | 0.000 | 0.001 | 安全 |
| 橫線 | homography | 0.000 | 0.000 | 0.000 | 安全 |
| 縱線 | uniform | **0.496** | 0.236 | **0.271** | **頂底不過**（各超 0.25 閘 1.1–2.0 倍） |
| 縱線 | 只縮放不修斜率 | 更差（全幅 p2p 0.76–1.00） | | | **不可行** |
| 縱線 | homography（rectify） | ≤0.02（帶內等距殘差 p95 1.7px） | | | 安全 |

一句話：**橫線 affine 就夠，縱線非單應性不可。**
而既然 `(VP_X, K)` 一組參數就同時決定兩軸（`row ∝ s²`、`col ∝ s`），
拆成「橫線 affine ＋ 縱線 rectify」比直接用單應性參數更多而不是更少。

`reason=recentred` 為 21）。這與量測結果自洽。

## 6. 選型建議

**採用完整平面單應性，並且把重點放在縱線的逐列重取樣（rectify），不是橫線的格距曲線。**

理由：

1. 縱線是唯一真正過不了 0.25 格閘的軸（頂帶 max 0.496、底帶 0.271 格，見 §3.3、§3.5）。
   橫線的均勻模型全域偏差只有 0.178 格，它自己不會殺人；殺人的是縱線。
2. 「只修 y 依存不修斜率」被實測否決（p2p 反升到 0.76–1.00）。
3. 單應性不比 affine 貴。`row ∝ s²`、`col ∝ s` 由同一組 `(VP_X, K)` 決定
   （實測比值 1.98／2.26），參數量是 `(VP_X, K, col_p0, row_p0)`；
   拆成兩軸各自 affine 反而要 `(col_p0, col_k, row_p0, row_k)` 四個，
   還失去兩軸互相驗證的能力。
4. `board.rectify_columns` 已經實作了正確的重取樣，常數 `PERSPECTIVE_VP_X=1166`、
   `PERSPECTIVE_K=1.10e-4` 也被本次獨立量測確認。缺口是 `read_lattice` /
   `find_lattice` 沒走它——只有 `scan_edges` 在用。這是既有正確機制沒有覆蓋到位，
   不是要發明新東西。
5. 但**單靠換模型不會讓 aim 閘過關**：§3.4 的週期不一致（中位 0.052、p95 0.156 格）
   與模型無關。相位比較的兩側必須改成同一個週期（都用世界格距，或都用當幀量測值），
   否則換完模型還會剩一個 0.15 格的系統項。

### 我不確定的地方

1. **K 與 VP_X 隨 zoom 變**。兩 run 差 2.5%，若換到別的縮放檔差多少沒量。
   建議錨定時當場量而不是寫死常數；`PERSPECTIVE_K` 目前是硬編碼的。
2. **參考列 y=650 是沿用 `PERSPECTIVE_REF_Y`**，我沒有獨立驗證這個選擇的合理性
   （它只是個平移基準，理論上不影響結果，但若實作用不同基準要一起改 `p0`）。
3. **橫線分不出 affine 與單應性**。兩者幀內殘差同為 0.009 格，全域偏差 0.004 vs 0；
   1px 的像素量化下，25px y 帶的中位數解析度就是 1px，這個資料量分不開。
   我選單應性是因為**縱線需要它**且兩軸共參數，不是因為橫線上量得出差別。
4. **y>960 沒量**（底部訊息條干擾）。格網實際可延伸到 y≈1080，那一段的外推沒有證據。
5. **SCREEN_CENTRE 的 y 有 7–9px 的模型依賴**：環心 546 vs 格心 553–555。
   我取格心（因為 `recentre_offset` 用的是 `centre_of`），但這假設「光環精準畫在格心」；
   沒有第三方證人。建議實作留 ±5px 的餘裕。
6. **21 筆置中樣本全來自同一關 `uc_hard_1` 的同一批我方單位**。不同體型的環半徑
   在 50–58px 之間變動，但環心散布仍只有 ±2px，體型影響應該不大——不過沒有跨關卡樣本。
7. **沒有做跨幀的單應性驗證**。我證明了「螢幕空間的格距場與鏡位無關」（p10/p90 ±1px），
   這是必要條件；但「pan 之後同一世界列的螢幕位移確實符合單應性」需要非模型來源的
   位移真值（界線背書幀），本次沒做。這一項如果要補，是實機驗證佇列的題目。
8. **`run_031256` 的 row/col 相對斜率比值 2.26 偏離理論值 2.0 約 13%**
   （011740 是 1.98）。可能是 1px 量化在斜率較小的縱線上放大，也可能是別的；
   沒有查清楚。這不影響選型（兩軸仍明顯是 1:2 量級），但如果之後要把兩軸綁成
   同一組參數，這 13% 要先解釋掉。
