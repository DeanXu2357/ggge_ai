## 一、一個 tick 的執行順序（`BoardDriver.survey_board`）

外層契約與 v2 完全相同：一次呼叫至多一個微步驟，`drivers()` 介面不變。

```
survey_board(action, observation)
 ├─ 還沒縮放 → _zoom() → 回 "zoom"（縮放改比例，整個世界作廢重來）
 ├─ _settled_capture()                     等畫面靜下來再收幀（未改）
 ├─ _read(precheck, leg=None, …)           → Survey.observe(frame)
 ├─ Survey.plan_leg()                      → 這一把往哪推；None ＝ 沒得推
 │    └─ None → "done"／"fuse"／"stuck"
 ├─ stance = Survey.stance                 ← 一定要在 plan_leg 之後讀
 ├─ _pan(leg, pick_pan_origin(...))        送出平移手勢（未改）
 ├─ _read(leg, leg, _settled_capture())    → Survey.observe(frame, leg)
 └─ 回 f"{stance}:{leg.direction}"         例：zero:west／tour:east／fill:north
```

微步驟名從 `sweep`／`blind` 換成 `zero`／`tour`／`fill`（`STANCE_STEPS`），
`done`／`fuse`／`stuck`／`zoom` 不變。流水帳讀者（`scripts/replay_run.py`）只吃通用
欄位，不必改。

## 二、一幀怎麼定位（`Survey.observe`）

```
observe(frame, leg)
 ├─ still = _unchanged(previous, frame, leg)      畫面到底有沒有動（只回布林）
 │    ├─ 兩幀幾乎逐像素相同                        → 沒動
 │    ├─ 相位相關量得到位移                        → 量到多少算多少
 │    ├─ 量不出來且沒有指令                        → **當作動過**
 │    └─ 量不出來但有指令 → null_check 判「確定沒動」才算沒動
 ├─ _tally(leg.direction, still)                  推不動的次數；連兩次記下夾點
 ├─ stance == zero → _zeroing(frame)
 │    ├─ 兩個方向都還沒連兩次推不動 → 回 ZEROING（一格都不寫）
 │    └─ 都推不動 → _anchor(frame, view)
 │         ├─ 角落那兩側一條終止邊都看不到 → 不敢認，退一步再來（ZERO_TRIES）
 │         ├─ 已有舊圖而角落與舊地標矛盾 → _forget()（整張作廢重來）
 │         ├─ 沒有舊圖 → read_lattice → WorldGrid.anchor
 │         └─ located = (frame, (0,0))；stance → tour
 └─ 否則 _place(frame, still)
      ├─ _locate(...)
      │    ├─ _from_landmarks(view, "x") / (…, "y")
      │    │    同軸兩側都看得到而差超過半格 → 丟棄（edge_mismatch）
      │    ├─ 兩軸都讀得到 → 座標定案（source=edge）
      │    ├─ _recall(...)  ← 只補讀不到地標的那一軸
      │    │    ├─ 畫面沒動且上一張定位成功 → 沿用它（source=still）
      │    │    ├─ _drift：跟最近一張定位成功的幀量重疊區位移（source=drift）
      │    │    └─ _constellation：單位排列比對回已記目擊（source=match）
      │    ├─ 直線軸沒有地標時走 _snap（格線相位交叉驗證＋吸附），對不上就丟棄
      │    └─ _corroborated：重疊區量到的位移要和候選座標對得上（半格內）
      │         量不出重疊位移時退回 null_check（只問「這個位移是不是根本沒發生」）
      ├─ 解不出來 → _discard()：unlocalised+1、知識圖一格不動、連丟三張推回角落
      └─ 解得出來 → chart.absorb(placed) → _learn_edges(placed) → located 更新
```

**地標**（`Survey.landmarks`）＝四側地圖終止邊的世界像素。定位成功的幀看到哪一側就
記哪一側；往後任何一幀看得到同一側，那一軸就是 `地標 − 它在螢幕上的位置`。第一次
記下就不再改。

## 三、階段機（`plan_leg`）

| 階段 | 推什麼 | 何時換階段 |
| --- | --- | --- |
| `zero` | 依序往西、往北，用得到的最大手指行程 | 兩個方向都連兩次推不動＋角落至少一側看得到終止邊 → 錨定 → `tour` |
| `tour` | 東 → 南 → 西，每側推到終止邊進畫面或連兩次推不動 | 三個方向都走完 → `fill` |
| `fill` | 朝待掃格聚類推（`_aim`），沒得挑就往還沒定界線的方向探（`_probe`） | 沒有待掃格且四面界線都定 → `plan_leg` 回 None |

`_aim` 算的是「把目標格**推進偵測帶**還差多少」（`_needs`），不是「離視野中心多遠」；
目標已在帶內卻仍是缺口＝壓在 HUD 挖洞底下，改算挪出洞的最小一步（`_escapes`）。
兩者都推不動才把那一格退休（`unreachable`，明寫進流水帳）。

## 四、保留／降級／退場對照（提案第三節）

**原樣保留**：單位偵測與密度峰、格線讀取（含象限窗）、地圖終止邊偵測、HUD 挖洞、
格子存在遮罩（EMPTY 要格線背書）、界線定案後裁剪界外知識、同回合單位知識不因漏檢
降級、跨回合衰效、四態知識圖與待掃格補掃、影像複驗、平移手勢與取幀靜止閘、平移
次數保險絲（`LEG_BUDGET`，單回合失控保險）。

> **更正（修正輪）**：骨架批這一行原本寫「地圖終止邊偵測（含 v2.10 的邊緣位移量測）
> 原樣保留」，**不實**——`_edge_shift` 當時零生產端呼叫者，只剩自己的測試在用。修正輪
> 把它改名 `board.edge_shift`、接回 `coverage` 當複驗的獨立佐證，這一行才成立。

**降級**：逐步位移量測鏈 → `_drift`，只在讀不到地標的那一軸補位，而且要過格線相位
與一道**不是它自己給的**複驗（見第九節）。

**退場**：
- 定位中斷後位置不明的觀測暫存區（下稱島嶼）與整套重錨：`Island`、`ISLAND_BUDGET`、
  合併雙閘、與大陸（權威圖那一側）對質、`last_merge` 遙測欄。定位不出來就丟棄。
- 增益學習（`GAIN_*`、`_learn_gain`）：改用固定比例 `NOMINAL_GAIN`，只用來換算手指
  行程，不進座標。
- 推不動次數推論界線（`fix_boundary`／`edge_cell`／`_boundary`）：界線一律目視。
- `Odometer`：整個類別移除，由 `Survey.landmarks` ＋ `_locate` 取代。
- （修正輪追加）`board.measure_pan` 的整條格線相位通道（`_column_phase`／
  `_resolve_columns`／`_correlator_credible`／多路佐證裁決）、`board.envelope` 與
  `board.phase_residual`：v3 從不量「這一把推移走了多遠」來當座標，三者骨架批之後
  就零生產端呼叫者，連同測試誠實退場。

**v2.10 三爭點**：單位排列比對退居補位（爭點 1、2 影響面大幅縮小）；島嶼合併一致性
複驗隨機制移除消滅（爭點 3 結案）。

## 六、爭點清單（請使用者／主 session 裁示）

1. ~~**補中央的定位來源優先序與提案文字相反**~~ **（已裁示、已修正，見第九節）**。
   使用者裁示改回提案順序：單位排列比對優先，重疊區位移量測退居補位。單純對調確實
   會連環丟幀，所以修正輪同時把「一個候選過不了就丟整幀」改成「逐候選各自複驗、
   全部過不了才丟」。
2. **實機地標可得性存疑**（最該盯）。0719 那九張實幀裡只有兩張讀得到終止邊（皆為
   北側），其餘七張四側都讀不到。v3 的座標全靠地標，地標讀不到就退到補位那條路。
   實機第 8 輪必須先量「四個角落各推到底時，四側終止邊各讀不讀得到」——讀不到就得
   回頭調終止邊偵測或取樣帶，而不是調 v3 的骨架。
3. **`_needs`／`_escapes` 是提案沒有的抽象**（自創，提報待核准）。提案只說「朝缺口
   推」。實作改成「算差多少才進得了偵測帶」＋「壓在 HUD 挖洞底下就算挪出洞的最小
   一步」。理由：照原寫法在合成世界出現東西向來回各 100px 的活鎖，以及把暫時被回合
   橫幅蓋到的格當場退休（退休是跨代生效的）。
4. **敵方回合後固定回西北角，不是「最近的邊」**。提案寫「推到最近的邊重新歸零」，
   但敵方回合後鏡頭在哪本來就不知道，「最近」無從算起。改成固定西北角，換來的是
   跨代同一套世界座標（界線與地標不必重學）。代價是最壞情況多推幾把。
5. **`covered` 新增半格容差**。最外那一排格子的外緣就是終止邊，座標差幾個像素會把
   它整排切掉（合成世界實測 4px 誤差讓最南一列永遠蓋不到）。放寬的風險由界線定案後
   的裁剪收拾。這是 EMPTY 蓋章條件的鬆綁，請確認可接受。
6. **推不動要確認兩輪才能退休格子**（`bumped`）。提案把「推不動次數推論界線」列為
   退場，實作照辦（界線一律目視）；但規劃層仍留「推不動就別再往那邊推」的節流，且
   要兩輪才敢退休格子——連續兩把手勢被吃掉與真的到邊分不開，認一輪就封死會整欄退休
   （合成世界實測）。
7. **角落讀不出格網時的退一步重試**（`ZERO_TRIES=3`）。提案沒有規定。用完就
   `plan_leg` 回 None → `stuck`，該回合誠實掃不完。
8. **合成世界的虛空寬度是配著取樣帶挑的**（橫 600／縱 310），與實機幾何不同。它只
   保證「四側終止邊在各自角落都讀得到」這個性質受測，不代表實機比例。

## 七、設計決定（供併入 `docs/decisions.md`）

| 情境 | 選項 | 採用與理由 |
| --- | --- | --- |
| 敵方回合後從哪裡重新歸零 | (a) 推到最近的邊（提案文字）(b) 固定西北角 | **(b)**。敵方回合後鏡頭位置未知，「最近」算不出來；固定角落可重現，跨代回到同一套座標，界線與地標不必重學。 |
| 補中央讀不到地標時先問誰 | (a) 單位排列比對優先（提案文字）(b) 重疊區影像比對優先 | ~~(b)~~ → **(a)**（0803 使用者裁示推翻，見第九節）。連環丟幀的成因是「一個候選過不了就丟整幀」，不是順序；改成逐候選複驗之後 (a) 照樣收斂。 |
| 地標與比對結果衝突 | (a) 整幀丟棄 (b) 地標供該軸、比對供另一軸，合起來複驗 | **(b)**。地標是絕對量，用它否決整幀等於連確定的那一軸也丟掉；合起來對不對由重疊區複驗裁。 |
| 「畫面沒動」量不出來時 | (a) 當作沒動 (b) 當作動過 | **(b)**。(a) 會讓空白幀被判靜止、沿用上一張座標，下一張真的動過的幀就以舊座標寫進圖（合成世界實測長出兩格鬼影）。 |
| 最外一排格子被座標誤差切掉 | (a) 照舊（整排退休）(b) `covered` 給半格容差 | **(b)**。最外一排的外緣就是終止邊，數像素誤差不該讓整排永遠蓋不到；線外的由界線裁剪收拾。 |
| 瞄準待掃格的方式 | (a) 對準視野中心（v2）(b) 算「進偵測帶還差多少」 | **(b)**。(a) 在一軸已在帶內、另一軸夾在邊上時來回空推。 |
| 格子壓在 HUD 挖洞底下 | (a) 當場退休 (b) 算挪出洞的最小一步 | **(b)**。洞在螢幕座標固定，鏡頭一動格子就出來；退休是跨代生效的，不該用單一鏡頭位置的事實決定。 |
| 退休格子前要幾輪確認推不動 | (a) 一輪 (b) 兩輪 | **(b)**。連續兩把被吃掉的手勢與真的到邊分不開，認一輪就封死會整欄退休。 |
| 比對標的要不要含前一代的目擊 | (a) 含 STALE (b) 只含這一代的 UNIT | **(b)**。STALE 是敵方回合之前的站位，那些機體早就動過了。 |
| 角落讀不出格網 | (a) 無限重試 (b) 退一步重試三次後誠實停下 | **(b)**。無限重試會把整回合燒在原地；停下來是誠實的失敗，流水帳看得到 `stuck`。 |
| 定位路徑上的地標矛盾檢查 | (a) 保留 (b) 只留在歸零那條路 | **(b)**。定位路徑上該檢查是死碼（座標本來就是從地標算出來的，必然貼合）；歸零那條路的座標是被定義的，才需要跟舊地標對答案。 |
| 合成世界要不要有虛空外圍 | (a) 地圖鋪滿畫布（v2）(b) 四周包虛空 | **(b)**。v3 的座標全從目視的終止邊解出來，假世界不給邊就測不到骨架。`board.py` 的像素測試保留 (a)（`margin=NO_VOID`）。 |

## 九、修正輪（0803）：量測誠實缺陷

骨架批交出去之後的獨立驗證抓到**已重現的「量錯寫入」路徑**。以下逐項記處置。

### 9.1 起因：複驗與候選同源（P0-1）

`_corroborated`（骨架批 coverage.py:795）對 `_drift`（:740）導出的候選，拿**同一對幀
的同一個 `board.measure_shift`** 回頭當佐證。兩次呼叫之間 `self.located` 不會變、函式
確定性，所以 `implied` 恆等於 `measured`——那是恆等式，不是複驗。

實測（注入量測錯誤，其餘不動）：

| 注入的量測錯誤 | 閘門餘裕 x／y | 容差 x／y | 裁決（骨架批） |
| --- | --- | --- | --- |
| 0（乾淨） | 1.000／0.000px | 64／57.5px | accepted |
| y +230px（2 列） | 1.000／0.000px | 同上 | **accepted，知識圖整批下移 2 列** |
| y +300px | 1.000／0.000px | 同上 | **accepted，誤差 2.61 列** |
| x +256px（2 欄） | 1.000／0.000px | 同上 | **accepted，誤差 1.99 欄** |

非注入版同樣重現：用專案自己的 `freeze_correlator` 模擬 0801 相關器凍在靜態峰，四把
東向推移的第四把判 stalled／source=drift、offset 誤差 −896px，照樣被 `absorb` 寫進
知識圖（`_place` 的 absorb 在回 verdict 之前），長出兩格鬼影。

對照組（候選**不**從 `measure_shift` 導出）同一道閘正常否決 → 閘本身沒壞，壞在同源。

### 9.2 修法：複驗主判準換成佔位一致性

使用者裁示：複驗要用**已獲取的佔位資訊比對**（候選座標成立的話，畫面上這些機體
應該落在已記錄的哪些格），影像比對只是「中央帶剛好空曠無單位」時的消歧義手段。

`_corroborated` 現在這樣走（`coverage.py`）：

```
候選座標套上去 → 這一幀的機體落回知識圖已記的目擊幾台（_fits，半格內算對上）
 ├─ 同時算「差一整格的鄰居」配得幾台（兩軸各 ±1 格，共四個鄰居）
 ├─ 鄰居配到 2 台以上而且贏過候選 → 拒收（OCCUPANCY_REFUSED）
 ├─ 候選贏過所有鄰居 → 收（gate=occupancy）
 └─ 都配不上（沒有材料）／候選出自排列比對 → 走影像比對那一路（_pictured）
```

判準是**和鄰居比**而不是固定支持數門檻：往沒看過的地方推的幀，畫面上多數機體本來
就還沒被記過，湊不到固定門檻是物理不是矛盾（固定門檻 3 實測會把 22x12 合成世界的
正確幀擋掉一半）。基底 `9d072c7` 的 `Survey._agrees` 是同一條紅線的舊實作，本輪把
它的語意接回來當通用複驗器；`_agrees` 原本「零目擊就回 True」的預設放行**沒有**
沿用（v3 沒有當時的兜底），改成走影像比對那一路。

`_pictured`（影像比對這一路）的順序，**每一步都不得與候選同源**：

1. `board.edge_shift`（v2.10 的地圖終止邊位移，絕對量）——同一側在兩幀都讀得到時。
2. 排列比對導出的候選才問得起的重疊區 `measure_shift`（對它而言那是獨立的第二佐證）。
3. `_outbids`：`board.null_check` 逐窗把候選的位移拿去和**差一整格的鄰居**對質。

第 3 步的對手是鄰居而不是「有沒有動」，因為格線是週期訊號：差整數格的錯值照樣把
線對得整整齊齊，「動了沒」那個問法答不出來（合成世界實測，差兩列的錯值就是這樣
過關的）。改用鄰居當對手之後只有真值那一個位移能讓地表紋理也對上。

### 9.3 順帶修掉的閘門缺口

- **`_snap` 讀不出格線時放行**（P2-1）改成拒收。地圖邊緣與無特徵背景正是重疊區量測
  最不可靠的場合，而 x 軸唯一的閘就是它。
- **`null_check` 加 `slack`**：問「差一整格的兩個位置哪個對」時，兩個假設吃同一份
  對位餘裕（3px）。候選本來就帶幾個像素的量測誤差，逐像素硬比會連正確的假設一起
  判否。預設 0，既有呼叫端行為零改變。
- **`board.OVERLAP_PROBES`**：沒有機體可當窗心時，逐窗比對改用地圖區內均勻鋪的一片
  窗，且限在格線覆蓋的矩形內——星空那一層不隨鏡頭動，拿它問位移只會系統性地投給
  位移比較小的那個假設。

### 9.4 孤兒化的量測鏈（P0-2）

`measure_pan`／`_edge_shift`／`envelope` 骨架批之後零生產端呼叫者。裁決與執行：

| 對象 | 裁決 | 理由 |
| --- | --- | --- |
| `_edge_shift` | **接回來**，改名 `board.edge_shift`，簽名改吃「側名→螢幕座標」 | v2.10 本來就是為「獨立於像素量測的位移佐證」而做，正好是 9.2 第 1 步要的東西 |
| `measure_pan` 整條格線相位通道 | **退場**（含 `_column_phase`／`_resolve_columns`／`_correlator_credible`／`_nearest_candidate`／`_envelope_window` 與 `LATTICE_*`／`WITNESS_*` 常數） | 它量的是「這一把推移走了多遠」，v3 的座標從不由推移量得出；格線相位在 v3 由 `coverage._snap` 承接 |
| `envelope`／`phase_residual` | **退場** | 指令包絡閘只服務那條量測鏈；`phase_residual` 的呼叫端只剩測試（`median_residual` 另有生產端） |

測試一併退場：`tests/test_runtime_board.py` 的格線相位通道 11 條、`test_stage_survey.py`
的 `test_the_settle_gate_never_goes_through_the_commanded_channel` 改寫成「手勢的量
連量測都不閘」的守成斷言。

### 9.5 地標的矛盾檢查與回收路徑（P0-3）

東側與南側的**第一次**目擊必然發生在沿邊繞圈階段，那時該側還沒有地標 → 那一軸的
座標只能來自補位來源。地標寫下不再改、跨代保留，`set_boundary` 接著裁掉界外所有
知識——骨架批沒有任何回收路徑。本輪：

- 佔位一致性的鄰居候選**兩軸都試**，不只補位那幾軸。地標算出來的軸不會跟自己矛盾，
  這是唯一驗得到它的地方：整整差一格的地標會讓畫面上的機體整批落在隔壁那一欄，而
  隔壁那個候選配得比較好 → 當場拒收。
- 有地標背書的幀連著 `LOST_PATIENCE`（3）次被佔位一致性判否 → `_forget()` ＋推回
  角落重來。單獨一幀可能只是偵測漏，連三幀都有兩台以上機體指著隔壁那一格就不是巧合。
- 沿用上一張座標的幀（`SOURCE_STILL`）不再寫地標：那一幀沒有帶來新的位置證據。

**試過但退掉的做法**：先實作成「拿 `board.relocalise` 的全域比對去否決地標算出來的
軸」。合成世界實測誤殺——`SPREAD` 的欄距是等差的，排列比對在那裡投出差 1151px（9 欄）
的眾數，連著三幀否決正確的地標、把整張圖作廢重掃，`test_a_taller_world…` 因此不收斂。
排列比對的票本身就是骨架批爭點 1 的成因，拿它當唯一否決權等於把那個弱點放到最上游，
所以改用上面「鄰居配得比較好」這個要兩台以上才裁得動的條件。

### 9.6 退休格逐格進流水帳（P1-1）

`summary()` 增 `retired`（逐格點名，`[[col,row],…]`），`unreachable` 的計數保留。退休格
同時退出 `frontier()` 與 `gaps()`，所以 `complete` 可能在那幾格從沒被觀測的情況下成立
——只記個數的話那條路就是無聲丟失。

### 9.7 `bumped` 跨代未清（P2-2）

`reset()`／`_rezero()` 現在都清掉 `bumped`。退休格子要「推不動兩輪」，而重新歸零換了
一套座標，舊世界數到的那一輪併進新世界等於把兩輪弱化成一輪，而退休是跨代生效的。

### 9.10 修正輪之後仍有風險的地方（誠實列出）

1. **凍住的相關器底下掃不完**。修正輪保證「不長鬼影」，不保證收斂：合成世界
   30x16＋`freeze_correlator` 跑 90 tick 的結果是 `unlocalised=33`、重新歸零 11 次、
   `synced=False`、記到 2 台（真值 9 台，**無鬼影**）。這是誠實的失敗而不是量錯寫入，
   但實機上如果水平相關器常態凍住，掃描就完不成——實機第 8 輪要量這件事。
2. **沒有機體、也沒有地圖終止邊的畫面定位不出來**。那種幀只剩逐窗影像比對，而它在
   完全無特徵的地帶回 `unclear`／`blind` → 丟棄 → 連三張推回角落。提案本來就寫「對
   不回來就重新歸零」，成本有上限，但實機上中央帶如果又空又平，重新歸零的次數會比
   估計多。
3. **`_outbids` 的 3px 餘裕是對著合成世界的地表（逐像素白噪）調的**。實機的地表美術
   有空間結構，同樣的餘裕會更寬鬆而不是更嚴格，但這個數字沒有實幀證據。
4. **地標仍然「第一次寫下就不再改」**。修正輪加的是矛盾檢查與整張作廢重來，不是就地
   修正。差一格以上、而且佔位一致性沒有材料（該側附近沒記過機體）的地標錯誤，目前
   仍然抓不到。
5. **排列比對導出的候選，其獨立佐證是 `measure_shift`**，而 `measure_shift` 在信賴度
   低時會退到幀對幀的排列投票。兩者的輸入不同（已記目擊 vs 前一幀），但在極端情況下
   （知識圖的目擊幾乎全來自前一幀）獨立性會變弱。沒有實測案例，列為已知殘餘。
