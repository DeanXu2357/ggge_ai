# 實機迴圈坑冊

十八輪實機跑出來的坑，逐條寫成「現象／根因／守則／證據」。**動實機迴圈的碼之前先讀這一份**
——這裡每一條都是燒掉一整輪才換到的。

守則欄寫的是可以直接照抄的紀律；證據欄是那一輪的 run 目錄或截圖，`data/runs/` 是 gitignored，
沒了就以流水帳的引述為準（review 文件裡有摘錄）。

---

## 1. 單發 classify 撞轉場＝誤判

- **現象**：點開詳情頁的第一格被判成「列表盡頭」，整段名冊只讀到一台。
- **根因**：詳情頁開場有轉場動畫，單發 `screens.classify` 會在動畫中途讀到底下那一層。
- **守則**：面板判定一律**輪詢**；「盡頭」這種終止判定要**連續兩輪**同樣的答案才算數
  （`SCREEN_ATTEMPTS`／`END_OF_LIST_CONFIRMATIONS`）。
- **證據**：run `20260806-024307`。

## 2. 淡入轉場：`classify` 過了不代表這一頁畫完了

- **現象**：`enemy#16` 的詳情頁陣營帶紅／藍佔比雙雙 0.000，HP／EN／移動力同時讀成 None。
- **根因**：半透明淡入幀的**形狀**還在（字模過得了），**顏色與筆畫**被稀釋掉。
- **守則**：讀值之前先 `steady(讀值區)` 等那一塊停下來；讀不齊就**重拍重讀**（最多三次）。
  真正的保險是重試，不是把門檻調鬆。
- **證據**：run `20260806-120326`。

## 3. 危險帶誤攔與 intent

- **現象**：面板上的正常點擊被安全機制擋下來。
- **根因**：`device.DANGER_BANDS` 的範圍比可見鈕大（帶要包住鈕在各畫面的所有位置），
  面板疊上來時會產生假重疊。
- **守則**：帶不放寬，改讓**知道自己在做什麼的呼叫端帶 intent**（`roster_cell`／`roster_jump`
  ／`ally_dismiss`）；intent 是白名單，不是繞道。

## 4. UI 遮罩 vs 危險帶：誰是權威

- **現象**：挑「空白格」挑到 (2238,1011)，撞上 weapon_dial 帶。
- **根因**：遮罩矩形是照著看得見的 UI 畫的，追不完帶的形狀。
- **守則**：`UI_EXCLUSION_ZONES` 只是第一層粗篩，**能不能點下去問 `device.blocked_for_map_tap`**
  ——它才是權威。
- **證據**：0806 run（`jumpscan.UI_EXCLUSION_ZONES` 的註解）。

## 5. escape 盲點把卡條打開了

- **現象**：`attack_fit` 38 → 1、`land_failed` 37（清一色 `grid_unreadable`）、`escape_map` 31。
- **根因**：(1798,971) **在行動模式下**是「返回」，**在純地圖上**是「單位列表」開關。無條件
  盲點它會把卡條展開，蓋住地圖下緣，之後每一張幀都讀不出格網。
- **守則**：**先看畫面再決定**（`leave_action_mode`）：行動模式才按返回、面板走 close_panels、
  已經在地圖就什麼都不做、認不出來就回報失敗。**一律不盲點。**
- **證據**：run `20260806-141615`，證據幀 `frames/00038-tick0276.png`。

## 6. 「畫面對」不等於「盤面可用」

- **現象**：卡條展開的那些幀，`classify` 照樣回 `battle_map`，於是硬閘一路放行。
- **根因**：畫面名只回答「這是哪一頁」，回答不了「這一頁上我要用的東西還在不在」。
- **守則**：地圖點擊的前置條件是**兩件事**：`classify == battle_map` **且**卡條是收合的
  （`screens.read_roster_strip`）；讀不出來就拒絕點。
- **證據**：run `20260806-141615`。

## 7. 頂帶盲區：種標記種在標記看不見的地方

- **現象**：北向推鏡連 36 筆 `no_seed`，跟著 192 筆空轉的 escape。
- **根因**：`board.MAP_REGION = (150, 250, 1600, 620)` 是填色 learn／find 的權威區，而前緣
  排序專挑最北的 row 0/1（格心 y≈90-203）——點下去填色真的出現了，`find_marker` 卻看不到。
- **守則**：種標候選格心必須落在 **MAP_REGION 內**（`jumpscan.clean_points(inside=…)`）；
  「畫面上看得到」與「偵測器看得到」是兩個區。
- **證據**：run `20260806-173300`。

## 8. 貼界時前緣格在界外

- **現象**：`enemy#0` 貼近西界，(0,2)-(0,5) 連環點下去全是 `none`，整台退場。
- **根因**：前緣排序專挑最外側的格，而那幾格已經在地圖界外——點的是虛空。
- **守則**：候選先過**界檢查**（`jumpscan.inside_borders` ＋ `sweep.read_borders`）：看得見
  的那一側就排除界外格；看不見的那一側不表態。
- **證據**：run `20260806-210825`。

## 9. 假北界：HUD 下緣的脊被當成界

- **現象**：`enemy#3` 推了兩把、`travel=0`、卻「見到北界」，出了一個看起來很自洽的錯答案。
- **根因**：頂帶 HUD 蓋住格線時，`read_frame_grid` 把 HUD 下緣的脊讀成北界；假界與零行程互鎖。
- **守則**：兩層。(a) 北界以 **`sweep.read_borders`** 的終止邊特徵為權威，`FrameGrid.north_bound`
  只當佐證；(b) 出帳前跑**自洽守門**（`jumpscan.audit_march`）：每一把 pan 都要留下一筆 leg，
  而且推過就該走過（`pans≥1` 而 `travel<pans` ＝矛盾）。不過關就 `unresolved`。
- **證據**：run `20260806-173300`。

## 10. 手勢被吞：發出去 ≠ 生效

- **現象**：北推的標記位移呈現 0 與 4-5 交替（這把沒動、下把雙倍）。
- **根因**：省電觸控鎖等因素會**無聲吞掉整把手勢**，不是標記認錯。
- **守則**：**逐手勢驗收**（`marchkit.Marcher.pan`，搬自 sweep_scan）：標記像素位移是未包裝的
  證人、相位只在標記看不見時撐場；判定被吃就先 `ensure_unlocked(force=True)` 再把**同一把原樣
  重發**，連吃就停手。夾停（PINNED）與被吃（EATEN）要分開——夾停改方向即可，重發沒有意義。
  **推不動永遠不等於有界線。**
- **證據**：run `20260806-210825`；機制原型在 sweep 十二輪（`tests/test_sweep_scan.py` 的
  eaten／pinned 系列，已對應搬進 `tests/test_marchkit.py`）。

## 11. ±1：單腿 mis-snap

- **現象**：同落點幾何的兩台 travel 差 1（16 vs 17）。
- **根因**：某一把的標記 snap 抖了一格。
- **守則**：每一把把**標記位移**與**名義行程**（stroke ÷ 格距）對照，差超過 0.6 格就重拍重認；
  仍不符記 `leg_suspect`，該軸只要含存疑的腿就降級 `unresolved`——寧可少一台，不要差一格的毒帳。
- **證據**：run `20260806-173300`。

## 12. 標記紀律：沒驗收的點擊不算數

- **現象**：整幀寫進差一格距整數倍的世界位置。
- **根因**：點了就當標記種好了。填色沒出現在**被點的那一格**時，下一次重認拿舊填色配新格號。
- **守則**：`sweep.classify_tap` 回 `TAP_EMPTY` 才算數；說不出結果（`TAP_NONE`）**重拍重點一次**
  再判；記著的標記在當下這一幀看不見就當它沒了（`marker_gone`），不准拿幾何上的「應該在窗內」
  當證人。全套在 `marchkit.Marcher.place_marker`／`marker_gone`。
- **證據**：run `20260805-144856`（第 114 序種下的標記到第 124 序已不在畫面上，之後十圈沒再種過）。

## 13. 一趟要兩軸都齊＝白跑

- **現象**：`enemy#1` 的 x 量對兩次、`enemy#2` 的 x 量對兩次，全被丟掉，兩台最後都 `unresolved`。
- **根因**：帳是「整格」級的，一趟沒湊齊兩軸就整趟作廢，重試又把量對的那一軸重推一遍。
- **守則**：**帳是軸級的**（`JumpLedger.record_axis`）：一軸量到就入帳，回訪只補缺的那一軸；
  同台同軸再量到不一樣的值記 `axis_conflict`、**不覆寫**；`coords.json` 照實輸出單軸帳。
- **證據**：run `20260806-210825`。

## 14. 誤觸帳要機器查得到

- **現象**：某一輪誤下了一次移動指令，事後只能靠「那台的詳情頁少一顆鈕」反推。
- **根因**：驗收判準的「零誤觸」沒有機器可讀的答案。
- **守則**：每一次 map tap 之後看一眼 `classify`，落進 `MAP_SUBSTATES` 而又不是預期的那個模式
  就記一筆 `mistap`；`coords.json` 頂層帶 `clean_run`。
- **證據**：run `20260806-103335`。

## 15. 幀的時序：固定 sleep 拍到的是上一個鏡位

- **現象**：同一台四次落地算出四個不相干的格。
- **根因**：固定 `JUMP_SETTLE_S` 拍到的是「面板剛收、鏡頭還沒跳」的那一瞬。
- **守則**：等畫面**自己停下來**（`steady()`：連兩張在量測區的變化 < 0.06 才算落定），
  不要用固定秒數賭。
- **證據**：run `20260806-103335`。

## 16. 讀不出來就重拍，絕不沿用推鏡前那張

- **現象**：`pan()` 回 `None` 之後下一輪開頭拿 `None.grid` 直接 CRASH。
- **根因**：把「這一幀讀不出格網」與「沿用上一幀」混為一談。
- **守則**：鏡頭動過，舊視圖的格號全部作廢——重拍重讀一次（journal `march_reread`），
  還是讀不出來才計 lost。**沒有沿用這個選項。**
- **證據**：0806 第九輪。

## 17. 卡面圖案不得參與身分

- **現象**：接力帳把兩台同型量產機認成同一台。
- **根因**：`name_sig` 是卡面圖案雜湊，同型機不可分。
- **守則**：身分只由**數值反查名冊**（HP/EN 唯一才算數）或**位置證據**回答；卡面內容一律不讀。
  點擊只取「這一格有東西」這個 bit。
- **證據**：0806 使用者裁決。
