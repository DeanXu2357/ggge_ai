# 不停頓事件感知與流水帳完備性（issue #27）

定調日期：2026-07-20（與使用者逐輪討論定案）。前身 issue #23
（2026-07-13 已標記地圖砲感知缺口並預想對帳 fallback）——本文接手其
感知/同步/歸因範圍，#23 留「我方地圖砲執行端」尾巴。
優先序裁決：**對帳（批B）＋帳目閉合檢查（批C）＋資料保存（批A）先行**，
離線模擬強化與敵方策略假設庫（批G）往後排——一邊開發一邊累積數據，
每場實戰的紀錄從現在起就要可推導。

## 1. 問題定性：一整類「不停頓事件」，地圖砲是代表

現行感知模型的結構性假設：所有影響盤面的事件都會停下來跟我們互動
（應戰彈窗、戰鬥準備、垂死對話）。不符合的事件全部落在盲區：

- **敵方地圖砲**（MAP 兵器）：AoE、無應戰彈窗、一次打多台我方機。
- **敵 vs 第三方交戰**：整場在旁觀相位打完，雙方 HP 都變。
- **敵方自我 buff／補給／光環**。

後果：tracker 的 HP 信念只從我方交戰的 forecast/prep 讀數更新
（`_resync_board` 只修位置與數量），上述事件發生後信念安靜地錯到底，
solver 拿錯的血量規劃擊殺鏈。

### 使用者提供的遊戲知識（2026-07-20）

- **威脅圖示**：我方移動選格時，移動目標格內若在敵一般攻擊範圍顯示
  **驚嘆號**；若在地圖砲射程顯示**鎖定圖案＋驚嘆號**。預設自動顯示、
  無需切換鈕。＝遊戲在決策當下替我們算好威脅格。
- **敵方回合動畫**夾雜在各單位移動/行動之間，無法用時間估算截圖
  → 敵方回合即時偵測正式放棄。
- **戰況紀錄**：使用者無印象；網搜（game8/altema/kamigame/appmatch）
  查無此功能討論，當作不存在——對帳沒有 log 捷徑。
- **頻率偏低但大幅改變戰局** → 投資放在事前迴避與事後修帳，
  不放在事件捕捉。
- **地圖砲規格**：支援防禦無效；傷害只打我方單位（第三方免疫、
  不誤傷敵方）；必中、無反擊（網搜）；**移動前限定**（移動後不能發射
  → 威脅區錨定在敵機當前位置，本回合顯示的範圍＝下個敵方相位的完整
  威脅）；使用次數制。是否可暴擊未知，保守界先含暴擊倍率。

## 2. 設計原則

### 完備性標準＝離線可推導性

外層迴圈（打完 → 出去調陣容 → 再挑戰）需要用 sim 物件做大量離線推導。
離線推演的引擎不是重播過去（換陣容後軌跡從第一回合就分歧），是**從
生成模型展開未來**：定義檔開局＋公式（機制）＋敵方策略模型。因此：

> 一份紀錄是完備的，當且僅當「紀錄＋定義檔＋公式」足以把關卡生成
> 模型的每個成分識別出來。

這也是 stage-definition-requirements.md 開放問題 4（events 觀測記錄的
最小可行格式）的一般化答案。

### 即時單發不逆推；離線全場脈絡歸因

從單一 HP 差額逆推（哪台、哪把武器、暴沒暴）是欠定問題，live loop
不做。但離線、全場脈絡、跨場累積的條件下同一問題是超定的：

- **地圖砲歸因**：定義檔說全場只有 e05 有 MAP 武器＋圖示量過的範圍
  恰好蓋住受災格 → 事件唯一解（e05 於第 N 回合發射、剩餘次數 −1、
  傷害樣本入帳）。
- **暴擊識別**：逐交戰「公式期望 vs 實測」殘差跨場聚類——×1.0 與
  ×暴擊倍率兩群，比例估暴擊率。單發不可知，樣本群可識別；sim 的
  chance 節點要的本來就是機率與倍率。

### 不確定性收在保守界

站位安全評估取悲觀上界（含暴擊倍率）；forecast 傷害維持保守下界
教條（KILL 才確定擊殺）。變數多的工程解不是逐一解出，是讓每個變數
只需要一個夠安全的界。

## 3. 批次規劃

### 批A 資料保存：turn-boundary 盤面信念快照

- ledger 現有 `factions` 快照只有各陣營座標；新增（或擴充為）
  `board_belief` 事件：每回合我方回合開頭記一筆
  `[{uid, faction, world_pos, hp, en, alive, source, hp_turn}]`。
- `BoardTracker.UnitBelief` 加 HP 鮮度欄（`hp_turn`，仿 `pos_turn`）：
  記「這個 HP 是第幾回合從畫面確認的」——閉合檢查與對帳都需要
  區分新鮮讀值與陳舊信念。
- 純離線可測（fake tracker → snapshot → jsonl 斷言）。

### 批B HP 對帳（audit 層）

- 命名 **audit**，與 `reconcile.py` 分工：reconcile＝我方單發攻擊的
  sim/forecast/結果三層歸因；audit＝回合層級、涵蓋我們沒看到的事件。
- 騎既有數值讀點，不加專屬截圖：選單位後的單位卡、敵方摘要卡、
  weapon-select／battle-prep forecast——凡讀到數值 HP，與信念比對。
- 容差外 → ① 修信念（畫面權威，既有紅線）② ledger 記
  `unattributed_damage`：uid、預期 HP、實測 HP、差額、turn、格位、
  信念鮮度。這是離線歸因的原料，live 不做任何解釋。
- 敵方 HP 沿用「擊殺鏈前點開重驗」教條，重驗即對帳。
- 開放問題：容差怎麼設（OCR 誤差 vs 真事件的分界；可先取
  max(絕對值, HP 比例) 雙門檻，實測校準）。

### 批C 帳目閉合檢查（離線工具）

- `scripts/audit_run.py`（暫名）：讀 `data/runs/<ts>/battle_NN.jsonl`
  ＋定義檔，把每回合每單位的 HP 變化分配給具名事件（交戰信封、
  kill_check、unattributed_damage 歸因候選），輸出**未解殘差率**
  ＝紀錄完備性分數。
- 用途：① 完備性量尺（殘差高＝感知有洞，直接進歸因表「該修程式」
  欄）② 感知回歸工具（改 vision/tracker 後跑舊流水帳比對閉合率）。
- 第三方單位 HP 信念稀疏，閉合檢查對其只要求「方向一致」不要求
  逐點閉合（開放問題，實作時定）。
- **2026-07-21 落地（a16fe41）**：核心在 `agent/closure.py`（比照
  attribution 薄殼慣例）；分數＝「隱含歸功」（分母=快照間 gross 移動、
  分子=分母−非擊殺殘差），不逐事件分配——sig-keyed 交戰事件與
  uid-keyed 快照離線無映射，交戰事件僅 enrich 報表；`--stage-def`
  **刻意未接**（schema-3 定義檔 positions_only 對 HP 閉合無權威貢獻，
  日後需要時當純報表 enrichment 補上，非漏做）。第三方=方向違規
  flag、不入分數。

### 批D 地圖砲樣本蒐集協議（被動、遇到才做）

- 遇到有 MAP 敵機的關卡：`scripts/capture.py` 存
  ① 移動選格畫面（格內含驚嘆號／鎖定＋驚嘆號兩類圖示，多格多樣本）
  ② 該敵機武裝面板（MAP 武器列）。
- 存 `tests/fixtures/vision/threat_icons/`（PNG，像素級圖示分類，
  遵守 hp_arc 的 PNG-only 教訓）。
- 寫進 roadmap 暫停快照常備提醒，蒐到樣本前批E 不開工。

### 批E 威脅圖示偵測器（有樣本後）

- 逐格模板分類：無圖示／驚嘆號／鎖定＋驚嘆號。掛在移動選格流程，
  讀值記 ledger `threat_icons` 事件：格 → 類別＋當時敵方位置快照。
- 價值雙重：① solver 站位決策的權威威脅格（驚嘆號＝遊戲替我們算的
  1.5-ply 站位安全，自算威脅模型降級為深搜尋假想局面用＋互相校驗）
  ② 免費射程實測——累積讀值直接變成定義檔 MAP 範圍／敵武器射程
  的資料。

### 批F sim MAP 建模（搭第二階段 inspect_unit 同批）

- 武裝分頁讀到 MAP 武器 → sim 建模：只打我方（第三方免疫）、必中、
  無應戰節點（我方 max 節點不存在）、無支援防禦、移動前限定
  （威脅錨定敵當前位置）、次數制。暴擊未知先含倍率取保守界。

### 批G 敵方策略擬合假設庫（往後排，使用者裁決）

- 目標＝**行為等價的預測模型**，非復刻決策函數。
- 方法＝假設庫擬合（SRPG AI 原型庫是機制：打最近／打最弱／打可擊殺
  ／迎擊圈／固守／條件切換模式），每台敵機一個計分板，觀測到的
  決策逐筆裁決假設；幾十筆決策足以在數個原型間收斂。
- 觀測來源都已在規劃內：回合邊界位移 diff（批A）、應戰彈窗（S9d）、
  地圖砲離線歸因（批C）、警戒圈從移動史＋我方位置夾出。
- **量尺**：fitted model 事前預測每台敵機決策、事後對答案，逐機
  維護預測準確率；高於門檻 → solver 深搜尋用策略模型展開，低於
  門檻 → 退 min 節點保守處理。
- 已知限制與緩解：覆蓋偏差（滾動重規劃＋min 兜底）、平手雜訊
  （計分容忍）、模式切換（原型庫含條件切換假設；腳本類歸 events）、
  真隨機（擬合成機率分佈，expectiminimax 原生支援）。
- 紅線：原型庫＝機制（程式碼）；每關每機擬合結果＝process-scoped
  黑板信念，**不入檔**（維持 stage-definition-requirements 的
  「敵 AI 傾向不入檔」線；使用者 2026-07-20 確認放棄跨執行留存，
  代價＝每次新 process 幾場熱身重新收斂）。
