# 主迴圈要支援的情境（整理清單）

> Type: working—#95 期間的情境清單；#95 結束前經使用者同意後刪除

起始日：2026-10-05。主迴圈要支援哪些情境，到目前為止沒有定義。本檔
整理已經記錄過的情境與出處。每個情境由穩定的主迴圈處理，還是由可抽換的
plan controller 處理，記在第 5 節；使用者自 2026-10-07 起逐條裁定。

出處中的「§」指 `docs/roadmaps/replan-main-loop.md` 的章節。

## 1. 遊戲與裝置本身的條件

任何實作都要面對（出處：§4.1）。

| # | 情境 |
|---|---|
| 1.1 | 狀態只能從像素推得。 |
| 1.2 | 送出的手勢不一定生效：省電觸控鎖、系統鎖會無聲吞掉手勢。 |
| 1.3 | 轉場與動畫期間的幀不能當判定依據；地圖有常駐的待機動畫。 |
| 1.4 | 同一座標在不同畫面是不同的鈕，部分誤點無法復原。 |
| 1.5 | 地圖鏡位沒有絕對讀數；推鏡會被邊界夾停。 |
| 1.6 | 點擊格子有副作用：我方進入選擇態並置中，敵方出卡。 |
| 1.7 | 轉場時間長短不定：開場運鏡約 15 秒，下載對話框最長 60 秒。 |

## 5. 歸屬

controller 建立的閉包裡（§5.12.9、§5.12.14）。observe 只把靜止的幀傳入
plan controller，plan controller 在內部把幀辨識成證據（§5.12.15）。
